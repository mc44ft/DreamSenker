# 任务系统实现逻辑链整理

## 当前结论

当前项目没有独立的任务系统。

现有“任务”本质是：

- 对话触发器负责选择对话图。
- 对话图节点负责打开任务 UI。
- `GameManager` 负责把对话事件转成具体面板。
- `TaskPanel` 负责接受、拒绝、交付按钮。
- `GameSaveData` 和背包数据负责保存任务相关状态。

也就是说，当前任务系统是“对话系统驱动的轻量任务流程”，不是 `TaskManager + TaskData + TaskState` 这种独立结构。

## 主要脚本

| 脚本 | 当前职责 |
| --- | --- |
| `DialogueNpcTrigger` | 玩家按上键和 NPC 对话，按条件选择 Main / Tail 对话图 |
| `DialogueOneTrigger` | 玩家进入触发区后自动播放一次性对话 |
| `DialogueNpcTriggerInfo` | 配置 NPC 对话图、触发条件、对话 GUID |
| `DialogueOneTriggerInfo` | 配置一次性对话图、触发条件、对话 GUID |
| `DialogueNodeExternalUI` | 对话图中打开外部 UI 的抽象节点 |
| `DialogueNodeTaskPublish` | 对话图中打开任务发布面板的节点 |
| `GameManager` | 监听对话 UI 事件，并打开 `TaskPanel` |
| `TaskPanel` | 展示任务发布 / 任务交付按钮，并把选择结果回传给对话图 |
| `GameSaveData` | 保存对话是否触发、是否拾取晨露梦核等状态 |
| `InventoryManager` | 提供任务物品移除入口 |
| `ItemPickUp` | 拾取晨露梦核后写入背包，并设置 `IsGotChen = true` |

## 对话触发链

```text
玩家进入 NPC 触发区
  -> DialogueNpcTrigger.OnTriggerEnter2D()
  -> 显示 world tips

玩家按上键
  -> DialogueNpcTrigger.Update()
  -> 禁用玩家输入
  -> 禁用 UI 输入
  -> 隐藏 GamePanel
  -> CameraManager.EnterDialogue(transform)
```

之后 `DialogueNpcTrigger` 会遍历 `m_dialogueInfoArray`。

```text
foreach DialogueNpcTriggerInfo
  -> GameManager.CheckGameCondition(info.eGameCondition)
  -> 不满足则跳过
  -> 满足则判断 guid 是否已经触发过
```

分支规则：

```text
guid 没触发过
  -> 播放 GraphMain
  -> 对话结束且 shouldSave = true
  -> 写入 GameSaveData.TriggeredDialogueGuidList

guid 已触发过
  -> 播放 GraphTail
```

对话结束后恢复：

```text
CameraManager.ExitDialogue()
UIManager.ShowPanel<GamePanel>()
InputManager.SetPlayerInputAction(true)
InputManager.SetUiInputAction(true)
GameManager.SaveDataAll()
```

## 任务发布链

任务发布由对话图节点触发。

```text
DialogueNodeTaskPublish.OnExecute()
  -> DialogueNodeExternalUI.OnExecute()
  -> 监听 Dialogue_PanelFinished
  -> DialogueManager.FadeOutDialogueBox()
  -> DialogueNodeTaskPublish.ShowPanel()
  -> EventCenter.EventTrigger(Dialogue_ShowPanel, TaskPublishPanel)
```

`GameManager` 接到事件后打开任务面板：

```text
GameManager.OnDialogueNodeShowPanel()
  -> case TaskPublishPanel
  -> UIManager.ShowPanel<TaskPanel>()
  -> panel.Initialize(TaskPanel.E_PanelMode.Publish)
```

`TaskPanel.Initialize(Publish)` 做的事：

```text
m_publishButtons.SetActive(true)
m_deliverButtons.SetActive(false)
m_acceptButton.onClick += AcceptOnClick
m_rejectButton.onClick += RejectOnClick
```

玩家接受任务：

```text
TaskPanel.AcceptOnClick()
  -> GamePanel.SetTopBarActive(true, "寻找晨露梦核 位于树冠顶地图左侧")
  -> 播放按钮音效
  -> EventCenter.EventTrigger(Dialogue_PanelFinished, index = 0)
  -> UIManager.HidePanel<TaskPanel>()
```

玩家拒绝任务：

```text
TaskPanel.RejectOnClick()
  -> 播放按钮音效
  -> EventCenter.EventTrigger(Dialogue_PanelFinished, index = 1)
  -> UIManager.HidePanel<TaskPanel>()
```

`DialogueNodeExternalUI` 收到 `Dialogue_PanelFinished` 后：

```text
OnPanelFinished()
  -> 记录 args.Index
  -> DialogueManager.FadeInDialogueBox()
  -> OnFinished()
  -> Finished() 中移除 Dialogue_PanelFinished 监听
```

当前代码里 `_nextNodeIndex` 被记录了，但自定义选择下一个端口的逻辑被注释掉了，所以目前按钮 index 是否真正影响后续对话分支，需要看对话系统基类的默认行为和当前图配置。

## 任务物品链

当前任务物品是 `EPackageItemType.Chen`。

拾取链路：

```text
玩家进入 ItemPickUp 触发区
  -> 显示 world tips

玩家按拾取键
  -> InventoryManager.TryAddItem(EPackageItemType.Chen)
  -> GameManager.Instance.GameSaveData.IsGotChen = true
  -> Destroy(item gameObject)
```

`IsGotChen` 是当前任务交付条件的核心状态。

## 任务交付链

任务交付入口在 `GameManager` 中已经存在：

```text
GameManager.OnDialogueNodeShowPanel()
  -> case TaskDeliverPanel
  -> UIManager.ShowPanel<TaskPanel>()
  -> panel.Initialize(TaskPanel.E_PanelMode.Deliver)
```

`TaskPanel.Initialize(Deliver)` 做的事：

```text
m_publishButtons.SetActive(false)
m_deliverButtons.SetActive(true)
m_deliverButton.onClick += DeliverOnClick
```

玩家点击交付：

```text
TaskPanel.DeliverOnClick()
  -> GamePanel.SetTopBarActive(false)
  -> 播放按钮音效
  -> InventoryManager.RemoveItemFromPackage(EPackageItemType.Chen)
  -> EventCenter.EventTrigger(Dialogue_PanelFinished, index = 0)
  -> UIManager.HidePanel<TaskPanel>()
```

当前代码中没有找到 `DialogueNodeTaskDeliver` 脚本。也就是说，交付面板的打开逻辑在 `GameManager` 和枚举里存在，但脚本层只看到发布节点 `DialogueNodeTaskPublish`。如果交付能正常打开，入口可能来自已经序列化的对话图数据或未纳入当前脚本命名的节点；如果不能打开，这里就是缺口。

## 条件判断链

任务相关条件走 `GameManager.CheckGameCondition()`。

```text
DialogueNpcTrigger / DialogueOneTrigger
  -> GameManager.CheckGameCondition(EGameCondition)
```

当前和任务直接相关的是：

```text
EGameCondition.FoundChen
  -> return GameSaveData.IsGotChen
```

配合 `m_dialogueInfoArray` 的顺序，可以做到：

```text
优先检查 FoundChen
  -> 玩家已拾取晨露梦核
  -> 播放交付相关对话

否则检查 None
  -> 播放普通发布任务对话
```

这也是当前“判断打开交付面板还是任务发布面板”的主要实现思路：不是 `TaskPanel` 自己判断，而是对话触发器通过条件选择不同对话图，不同对话图再打开不同 UI。

## 当前状态保存

当前任务相关状态分散在两处：

```text
GameSaveData.TriggeredDialogueGuidList
  -> 记录某段对话是否已经触发
  -> 决定 NPC 后续播放 GraphMain 还是 GraphTail

GameSaveData.IsGotChen
  -> 记录是否拾取晨露梦核
  -> 用于 FoundChen 条件判断

PackageData.PackageDict
  -> 保存背包里是否还有 Chen 这个任务物品
  -> 交付时通过 InventoryManager.RemoveItemFromPackage() 移除
```

当前没有独立字段表示：

- 任务是否已接取。
- 任务是否进行中。
- 任务是否已完成。
- 任务奖励是否已领取。

这些状态目前靠“对话是否触发 + 是否拥有/拾取任务物品 + 对话图配置”间接表达。

## 当前问题

1. `TaskPanel` 会在 `Initialize()` 里反复给按钮添加监听，但 `OnHideFadedComplete()` 没有移除监听，多次打开可能重复触发。
2. 接受任务只显示顶部提示，没有写入明确的“任务已接取”状态。
3. 交付任务直接移除 `Chen`，没有先判断背包里是否真的有 `Chen`。
4. `IsGotChen` 在交付后没有重置，后续 `FoundChen` 条件仍然会返回 true。
5. 任务发布和交付的判断不在 `TaskPanel`，而在对话图条件和节点配置里，排查时容易误以为是面板逻辑。
6. 代码里没有独立的 `DialogueNodeTaskDeliver`，交付入口的脚本结构不完整。
7. 任务状态散在 `GameSaveData`、背包和对话 GUID 里，后续扩展多个任务会很难维护。

## 当前一句话链路

```text
任务不是由任务系统驱动，而是由对话触发器选择对话图，对话图打开 TaskPanel，TaskPanel 把按钮结果回传给对话图，任务物品和任务条件则临时挂在 GameSaveData 与背包数据上。
```
