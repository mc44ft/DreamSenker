# 背包系统调用关系与重构建议

## 结论

当前背包系统是一个轻量 UGUI 背包：数据存在 `PlayerSaveData.PackageData`，运行时由 `InventoryManager` 持有，界面由 `PackagePanel` 每次打开时重建。

你的当前目标只需要两类物品：

- 可使用道具：回血、回蓝、增益等，玩家可以在背包里主动使用。
- 任务道具：例如 `Chen`，用于任务或剧情判断，玩家不能在背包里主动消耗。

所以当前需要“格子展示 + 数量堆叠”，但不需要拖拽排序、装备、商店、制作系统。最优方向不是大换插件，而是把现有背包整理成“可使用道具 + 任务道具 + 格子堆叠显示”的清晰模型。

它现在能跑，但职责混在一起：UI 直接改背包数据，拾取物直接改特殊剧情状态，任务面板直接扣物品。建议先把“背包数据操作入口”和“物品类型规则”收敛到 `InventoryManager` 或后续的 `InventoryService`。

## 当前结构

```text
GameManager.InitializeGame()
  -> InventoryManager.SetupData(Player.PlayerSaveData.PackageData, PackageItemConfig)

InputManager
  -> EventCenter.InputUI_PackagePanel
      -> GamePlayUiController
          -> UIManager.ShowPanel<PackagePanel>()

ItemPickUp
  -> InventoryManager.AddItemToPackage(itemType)
  -> GameManager.GameSaveData.IsGotChen = true

PackagePanel
  -> InventoryManager.PackageData.PackageDict
  -> InventoryManager.GetItemInfoByID()
  -> InventoryManager.RemoveItemFromPackage()
  -> EventCenter.Game_BonusEffect

TaskPanel
  -> InventoryManager.RemoveItemFromPackage(EPackageItemType.Chen)
```

## 数据层

### `PlayerSaveData`

路径：`Assets/Scripts/Data/Runtime/PlayerSaveData.cs`

职责：

- 持有玩家存档数据。
- 其中 `PackageData` 是背包存档数据入口。

当前关系：

```text
PlayerSaveData
  -> PackageData
      -> Dictionary<EPackageItemType, int>
```

当前这个结构本质上已经支持复数道具：字典的 `int` 就是同类物品数量。

### `PackageData`

路径：`Assets/Scripts/Data/Runtime/PackageData.cs`

职责：

- 用 `Dictionary<EPackageItemType, int>` 记录物品数量。

特点：

- 没有容量。
- 没有固定格子容量概念。
- 没有物品实例概念。
- 同类物品天然堆叠。

这基本符合当前目标。只做可使用道具和任务道具，并且同类物品只需要数量堆叠时，`Dictionary<EPackageItemType, int>` 仍然够用。

但 UI 层要改：不要再“数量是多少就生成多少个图标”，而是一个道具类型占一个格子，在格子右下角显示数量。

### `PackageItemConfigSO`

路径：`Assets/Scripts/Data/Configs/PackageItemConfigSO.cs`

职责：

- 用 `EPackageItemType` 查 `PackageItemInfo`。
- 提供图标、描述、加成效果、加成数值。
- 后续应补一个物品分类字段，用来区分可使用道具和任务道具。

建议补充字段：

```text
EPackageItemCategory
  -> Usable
  -> Quest
```

这样 `PackagePanel` 不需要继续特判 `Chen`，只判断当前物品是不是 `Quest`。

当前问题：

- `GetItemInfoByID()` 每次用 `Where(...).FirstOrDefault()` 查数组。
- 数据量小时没问题，但更适合初始化时转成字典。

## 运行时入口

### `InventoryManager`

路径：`Assets/Scripts/Inventory/InventoryManager.cs`

职责：

- 持有当前玩家的 `PackageData`。
- 持有 `PackageItemConfigSO`。
- 提供添加、移除、查询配置方法。

调用来源：

- `GameManager.InitializeGame()` 初始化数据。
- `ItemPickUp` 拾取物品时添加物品。
- `PackagePanel` 使用物品时移除物品。
- `TaskPanel` 交任务时移除 `Chen`。

当前问题：

- 没有 `HasItem()` / `CanRemove()` / `TryRemove()`。
- `RemoveItemFromPackage()` 移除不存在的物品时静默失败。
- 不触发背包变化事件，UI 只能打开时重建。
- `PackageData` 公开暴露，UI 可以直接遍历内部字典。

## 拾取流程

### `ItemPickUp`

路径：`Assets/Scripts/Inventory/ItemPickUp.cs`

当前流程：

```text
玩家进入触发器
  -> 显示 worldTips

玩家按 Pickup
  -> 播放拾取音效
  -> InventoryManager.AddItemToPackage(itemType)
  -> 如果是 Chen，直接设置 GameSaveData.IsGotChen = true
  -> Destroy(gameObject)
```

当前问题：

- 拾取物直接知道 `GameManager.GameSaveData.IsGotChen`。
- 背包系统和剧情条件耦合。
- 没有“拾取成功 / 失败”的返回值，后续如果有容量限制不好接。

## UI 打开流程

### `InputManager`

路径：`Assets/Scripts/Managers/InputManager.cs`

流程：

```text
Input.GetButtonDown("Package")
  -> EventCenter.EventTrigger(E_EventType.InputUI_PackagePanel)
```

### `GamePlayUiController`

路径：`Assets/Scripts/Managers/GamePlayUiController.cs`

流程：

```text
收到 InputUI_PackagePanel
  -> 如果 PackagePanel 已显示，HidePanel
  -> 否则 ShowPanel<PackagePanel>(Middle)
```

评价：

- 这层职责合理，输入和具体 UI 面板没有直接绑死。
- `Debug.Log("背包操作")` 可以后续删掉。

## 背包面板流程

### `PackagePanel`

路径：`Assets/Scripts/UI/Panels/Inventory/PackagePanel.cs`

打开时：

```text
OnShowFadePreComplete()
  -> 播放 UI 音效
  -> Time.timeScale = 0
  -> 禁用玩家输入
  -> 遍历 InventoryManager.PackageData.PackageDict
  -> 每个物品数量生成对应数量的 PackagePanelItemIcon
  -> 读取 PackageItemConfigSO 配置
  -> 默认选中第一个物品
```

确认使用时：

```text
SureButtonOnClick()
  -> InventoryManager.RemoveItemFromPackage(selectedType)
  -> 图标回收到对象池
  -> EventCenter.Game_BonusEffect
  -> 背包空时显示空文本
```

关闭时：

```text
OnHideFadedComplete()
  -> Time.timeScale = 1
  -> 恢复玩家输入
  -> 回收所有图标
```

当前问题：

- UI 直接读 `PackageData.PackageDict`。
- UI 直接决定“使用物品 = 移除物品 + 发加成事件”。
- 每次打开按数量生成图标，同类物品 99 个会生成 99 个图标；这和“复数道具”目标冲突。
- 使用物品后只移除当前图标，没有刷新数量显示，因为当前 UI 没有数量显示。
- 关闭时没有清空 `_currentSelectedItem`，可能残留已回收对象引用。
- 打开空背包时没有主动设置空文本，可能残留上次描述。
- `Chen` 这种不可使用物品由 UI 特判。

### `PackagePanelItemIcon`

路径：`Assets/Scripts/UI/Panels/Inventory/PackagePanelItemIcon.cs`

职责：

- 显示一个背包格子里的物品图标。
- 后续应显示该物品数量。
- 保存当前物品类型、加成类型、加成数值。
- Toggle 选中时播放缩放动画，并通知 `PackagePanel`。

当前问题：

- 字段是 public，外部可随意改。
- 没有数量文本，不能表达复数道具。
- `OnPush()` 没有清理 Toggle 状态、回调、缩放 Tween。
- 复用对象池时，旧动画或旧选中状态可能残留。

## 外部系统调用

### 任务面板

路径：`Assets/Scripts/UI/Panels/TaskPanel.cs`

当前行为：

```text
DeliverOnClick()
  -> InventoryManager.RemoveItemFromPackage(EPackageItemType.Chen)
  -> EventCenter.Dialogue_PanelFinished
```

问题：

- 没有检查玩家是否真的有 `Chen`。
- 任务系统直接依赖具体背包枚举。

### 物品效果

当前行为：

```text
PackagePanel
  -> EventCenter.Game_BonusEffect(GameBonusEffectEventArgs)
```

评价：

- 用事件把 UI 和具体效果执行拆开是对的。
- 但“使用物品是否成功”和“是否移除物品”应该先由背包服务判断，不应该由 UI 直接决定。

## 当前主要问题

1. **背包数据入口不够封闭**

`PackageData.PackageDict` 被 UI 直接遍历。短期没事，长期会让任何系统都能绕过规则改背包。

2. **UI 承担了业务逻辑**

`PackagePanel` 不只显示，还负责使用物品、移除数据、触发效果。

3. **剧情状态写在拾取物里**

`ItemPickUp` 直接设置 `GameSaveData.IsGotChen`，这会让每个特殊物品都把剧情逻辑塞进拾取脚本。

4. **没有统一的操作结果**

添加、移除、使用都没有返回值。后续容量、任务检查、失败提示都会难写。

5. **缺少物品分类**

现在只能靠 `EPackageItemType.Chen` 这种具体枚举做特判。更合理的是在配置里区分“可使用道具 / 任务道具”。

6. **UI 没有堆叠格子**

数据已经支持复数，但 UI 没有数量显示，导致同类物品会被拆成多个图标。背包体验应该改成“一种物品一个格子 + 数量文本”。

## 推荐重构方向

### 第一阶段：先收口，不换 UI

目标：不大改表现，只把背包操作入口收敛，并明确两类物品规则。

新增或调整：

```text
InventoryManager
  -> HasItem(type, count)
  -> TryAddItem(type, count)
  -> TryRemoveItem(type, count)
  -> TryUseItem(type)
  -> GetItemStacks()
  -> CanUseItem(type)
  -> IsQuestItem(type)
  -> OnInventoryChanged
```

改动重点：

- `PackagePanel` 不再直接读 `PackageDict`，改用 `GetItemStacks()`。
- `GetItemStacks()` 返回每种物品一条数据，包含物品类型、数量、配置。
- `TaskPanel` 不直接 `RemoveItemFromPackage()`，改用 `TryRemoveItem()`。
- `ItemPickUp` 调 `TryAddItem()`，成功后再销毁。
- `PackagePanel` 不再特判 `Chen`，改用 `CanUseItem()` 决定确定按钮是否显示。
- 背包变化时触发事件，UI 可以选择刷新。

这是最该先做的一步，收益最大，风险最低。

### 第二阶段：拆出物品使用逻辑

目标：UI 不知道物品怎么生效。

建议结构：

```text
PackagePanel
  -> InventoryManager.TryUseItem(type)
      -> ItemEffectResolver
          -> EventCenter.Game_BonusEffect
```

处理方式：

- 普通回血、回蓝物品走 `Game_BonusEffect`。
- 任务道具标记为不可使用。
- UI 只根据 `CanUseItem()` 决定按钮是否显示。

### 第三阶段：清理特殊剧情耦合

目标：拾取脚本只负责拾取，不负责剧情。

推荐做法：

```text
ItemPickUp
  -> InventoryManager.TryAddItem(type)
  -> EventCenter.Inventory_ItemPicked

Quest / GameCondition 模块
  -> 监听 Inventory_ItemPicked
  -> 如果 type == Chen，更新 IsGotChen
```

如果暂时不想新增事件，也可以先把特殊处理收进 `InventoryManager`，但长期不如事件干净。

### 第四阶段：做格子显示，但不做拖拽

你的当前需求需要格子展示，但不需要拖拽排序。这里分清楚：

- 要做：背包格子视觉、选中状态、数量显示。
- 不做：拖拽、换位、装备栏、商店、制作。

当前 `Dictionary<EPackageItemType, int>` 可以继续作为存档数据，因为它已经能表达“某种物品有几个”。

推荐 UI 数据结构：

```text
InventoryItemStack
  -> EPackageItemType ItemType
  -> int Count
  -> PackageItemInfo Info
```

`PackagePanel` 根据 `GetItemStacks()` 生成格子：

```text
每种物品 -> 一个 PackagePanelItemIcon
PackagePanelItemIcon
  -> Icon
  -> CountText
  -> SelectedState
```

使用一个可使用道具后：

```text
InventoryManager.TryUseItem(type)
  -> 数量 -1
  -> 如果数量为 0，移除该类型
  -> PackagePanel 刷新该格子数量或重建列表
```

当前明确不做：

- 拖拽物品。
- 装备。
- 物品品质。
- 单个物品耐久。
- 同类型物品不同属性。

因此不建议现在升级为 `InventorySlotData` 模型。`InventorySlotData` 更适合“固定槽位 + 拖拽换位”，不是当前必须项。

只有以后明确要做以下功能，才需要新模型：


- 拖拽物品。
- 装备。
- 物品品质。
- 单个物品耐久。
- 同类型物品不同属性。

建议升级为：

```text
InventoryData
  -> List<InventorySlotData>

InventorySlotData
  -> ItemId
  -> Count
  -> SlotIndex
```

这一步不要急。只有明确要做拖拽、换位或装备时再上。

## 插件接入建议

如果后续接免费或付费背包插件，不要让插件直接替换全项目数据。

但按当前目标看，不建议优先接大型插件。大型插件通常会带格子、拖拽、装备、商店等能力，超出你现在的需求。

推荐边界：

```text
游戏系统
  -> InventoryManager / InventoryService
      -> 插件适配层
          -> 插件背包 UI / Store
```

保留自己的：

- `PlayerSaveData`
- `PackageData` 或升级后的 `InventoryData`
- 任务系统调用入口
- 拾取入口
- 存档格式

允许插件负责：

- 背包窗口 UI。
- Tooltip。
- 格子显示。
- 数量显示。
- 选中和描述展示。

这样就算插件以后不用了，也只换适配层，不会污染任务、存档、拾取系统。

## 最小推荐改造清单

优先级从高到低：

1. 给 `InventoryManager` 增加 `HasItem()`、`TryAddItem()`、`TryRemoveItem()`。
2. 给 `PackageItemInfo` 增加“可使用道具 / 任务道具”分类。
3. 增加 `InventoryItemStack` 只读视图数据，用来表达“物品类型 + 数量 + 配置”。
4. 让 `PackagePanel` 一个物品类型只生成一个格子，并显示数量。
5. 让 `PackagePanel` 用 `CanUseItem()` 控制确定按钮，不再特判 `Chen`。
6. 让 `TaskPanel` 交付任务前检查 `HasItem(EPackageItemType.Chen, 1)`。
7. 让 `PackagePanelItemIcon.OnPush()` 清理 Toggle、回调、缩放状态。
8. 打开背包前清空 `_currentSelectedItem` 和描述文本。
9. 把 `Chen` 的剧情标记从 `ItemPickUp` 里移出去。

当前不建议立刻做：

- 不建议马上引入完整格子背包数据结构。
- 不建议马上全量替换 UI Toolkit 或第三方插件。
- 不建议为了背包系统引入大型 DI 框架。
- 不建议把任务、装备、商店一次性塞进同一轮重构。
- 不建议做拖拽排序、装备栏、商店、制作系统。
