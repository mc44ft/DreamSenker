# 整体游戏架构整理

## 目标

这份文档只整理 DreamSenker 当前整体架构，用来快速说明项目不是“堆脚本”，而是按基础框架、编辑器工具、游戏业务、配置数据和表现资源分层组织。

核心讲法：`Framework` 提供通用能力，`PlayArk` 提供自研编辑器与图系统，`Scripts` 承载具体玩法，`Config` 用 ScriptableObject 驱动数据，`ArtRes / Prefabs / Scenes` 承载表现和场景资产。

## 总体分层

```text
Framework
-> 通用基础设施
-> Manager / UI / Event / Pool / Save / Load / Scene / Audio

PlayArk
-> 自研工具层
-> GraphCore / StateMachine / DialogueSystem

Scripts
-> 游戏业务层
-> Player / Enemy / Boss / Map / Quest / Inventory / Dialogue / UI

Config
-> 数据配置层
-> ScriptableObject / Graph Asset / MapDefinition / QuestDefinition / PackageItemConfig

ArtRes / Prefabs / Scenes
-> 表现与内容层
-> Sprite / Animation / Shader / Tilemap / UI Prefab / 地图场景
```

## 游戏启动主流程

```text
进入主界面
-> GameManager 显示 BeginPanel
-> 玩家开始或继续游戏
-> LoadGame 读取 GameSaveData
-> InitializeGame 初始化运行态
-> MapFlowController 加载当前地图
-> SpawnPointManager 提供出生点
-> GameManager 生成 Player
-> Player.Initialize 初始化玩家状态机与运行数据
-> InventoryManager 注入背包数据
-> QuestManager 注入任务数据
-> UIManager 显示 GamePanel
-> MapFlowController 初始化特殊地图状态
```

## 核心模块职责

### GameManager

项目运行态总入口。

- 负责开始游戏、读档、初始化游戏、生成玩家。
- 调用 `MapFlowController` 处理地图加载和传送。
- 持有当前 `GameSaveData`、`Player`、`PlayerMirrorEffect`。
- 处理 Boss 死亡、结局视频、返回主界面。

### Framework

通用基础设施层。

- `BaseManager<T>` / `SingletonMono<T>` / `SingletonAutoMono<T>`：全局管理器基础。
- `UIManager`：面板加载、显示、隐藏、层级管理。
- `EventCenter`：跨系统事件通信。
- `PoolManager`：对象池与数据池。
- `ResourcesManager` / `ABMgr` / `UWRResMgr`：资源加载。
- `RunningDataManager` / `JsonManager`：运行时数据保存与读取。
- `SceneTransition` / `MySceneManager`：场景切换与黑屏过渡。
- `AudioManager`：音乐和音效播放。

### PlayArk

自研工具和图系统层。

- `GraphCore`：通用节点图底层，封装 `GraphView`、节点、端口、连线、编辑器窗口。
- `StateMachine`：基于 GraphCore 的可视化状态机。
- `DialogueSystem`：基于 GraphCore 的对话图系统。

这一层是项目技术展示重点，能体现编辑器扩展、节点图设计、ScriptableObject 序列化和运行时驱动。

### Player

玩家运行时核心。

- `PlayerController`：玩家主控制器，继承 `StateMachineController`。
- `StateMachineController`：驱动当前状态机节点执行。
- `InputReader` / `Mover` / `Jumper` / `Attacker` / `AnimationPlayer` / `DamageableHealth`：玩家能力组件。
- `FormStrategy` / `FormSword` / `FormUnarmed`：不同战斗形态策略。
- `PlayerConfigSO`：玩家参数配置。

玩家系统的重点不是单个移动脚本，而是“状态机 + 组件化能力 + 配置接口”的组合。

### Enemy 与 Boss

敌人与 Boss 玩法层。

- `OldManController` / `OldManBrain` / `OldManActionDriver`：普通敌人控制、AI 判断和行为执行。
- `SpiderController` / `SpiderBossRoom` / Spider 状态类：蜘蛛 Boss 行为。
- `FoxBoss` / `FoxOneController` / `FoxTwoController`：狐狸 Boss 基类和阶段控制。
- `StateBase<T>`：传统泛型状态基类。
- `IDamageable` / `ITouchDamageable`：统一受击接口。

Boss 系统体现的是状态拆分、技能表现、场景房间控制和战斗反馈。

### MapSystem

地图流转和场景状态层。

- `MapDefinitionSO`：单张地图配置。
- `MapRegistrySO`：地图列表入口。
- `MapConnectionDatabaseSO`：地图连接数据库。
- `MapFlowController`：地图切换、传送、当前地图查询。
- `MapLinkPoint` / `MapLinkPointManager`：地图连接点。
- `SpawnPoint` / `SpawnPointManager`：玩家出生点。
- `SpecialMapCoordinator`：特殊地图逻辑。

地图系统的重点是“不是硬编码切场景”，而是用地图配置和连接数据库驱动地图流转。

### QuestSystem

任务状态和任务流程层。

- `QuestDefinitionSO`：任务配置。
- `QuestListSO`：任务列表。
- `QuestRuntimeData`：任务运行时存档。
- `QuestManager`：接取任务、判断可完成、完成任务、查询任务状态。
- `EQuestState`：任务长期状态。

任务系统和对话、背包、条件系统联动，不是孤立 UI。

### Inventory

背包和道具层。

- `PackageItemConfigSO` / `PackageItemInfo`：物品配置。
- `PackageData`：背包存档数据。
- `InventoryManager`：添加、移除、使用、查询物品。
- `InventoryItemStack`：背包 UI 展示数据。
- `PropEffectResolver`：道具效果解释器。
- `ItemPickUp`：场景物品拾取入口。

背包系统的重点是“配置数据 + 运行时数据 + UI 展示数据”分离。

### DialogueSystem

对话图和任务交互层。

- `DialogueGraph`：对话图资产。
- `DialogueNodeNormal` / `DialogueNodeChoice` / `DialogueNodeTaskPublish` / `DialogueNodeTaskDeliver`：不同对话节点。
- `DialogueManager`：运行时播放对话图。
- `DialogueNpcTrigger` / `DialogueOneTrigger`：场景触发入口。
- `DialogueBoxPanel`：对话 UI。

对话系统的重点是“节点图配置剧情流程”，并通过外部 UI 节点连接任务系统。

### Conditions

通用条件判断层。

- `ConditionSO`：条件资源基类。
- `ConditionContext`：条件判断上下文。
- `QuestStateConditionSO` / `QuestCompletableConditionSO`：任务条件。
- `SpiderBossAliveConditionSO` / `SpiderBossKilledConditionSO` / `FoxBossAliveConditionSO` / `MirrorMapClearedConditionSO`：地图和 Boss 条件。

条件系统让对话、任务、地图状态可以通过 ScriptableObject 组合，而不是写死在对话代码里。

### UI

游戏界面层。

- `GamePanel`：游戏内血条和任务追踪。
- `MainMenuPanel`：游戏内菜单。
- `PackagePage`：背包页。
- `QuestPage`：任务页。
- `TaskPanel`：任务发布和交付面板。
- `UsePanel` / `RestoreHealthPanel` / `BounsChoosePanel`：交互弹窗。
- `WorldTipsPunch`：世界提示。

UI 的主线是 `UIManager` 统一管理面板生命周期，业务系统只调用面板入口，不直接管理 Canvas。

### CameraSystem

镜头表现层。

- `CameraManager`：相机状态管理。
- `CinemachineVirtualCamera`：跟随相机和对话相机。
- `CinemachineConfiner2D`：地图边界限制。
- `CinemachineImpulseSource`：镜头震动。
- `OnTargetObjectWarped` / `InvalidateCache`：传送后刷新 Cinemachine 状态。

镜头系统的重点是地图切换、玩家传送、Boss 战和对话镜头之间的状态切换。

### Data 与 Config

数据配置层。

- `GameSaveData`：游戏整体存档。
- `PlayerSaveData`：玩家存档。
- `GameConfigSO`：初始游戏配置。
- `PlayerConfigSO` / `PackageItemConfigSO` / `QuestDefinitionSO` / `MapDefinitionSO`：核心配置资产。

项目主要用 ScriptableObject 配置静态数据，用 RuntimeData 保存运行时状态。

## 主要系统联动

### 任务对话背包链路

```text
NPC 触发对话
-> DialogueManager 播放 DialogueGraph
-> DialogueNode 判断 ConditionSO
-> QuestManager 查询任务状态
-> InventoryManager 查询任务物品
-> TaskPanel 显示发布或交付
-> QuestManager 修改 QuestRuntimeData
-> GamePanel / QuestPage 刷新任务显示
```

### 地图切换链路

```text
玩家进入 MapTransitionTrigger
-> GameManager.ChangeMap(pointGuid)
-> MapFlowController 查询 MapConnectionDatabaseSO
-> SceneTransition 加载目标场景
-> SpawnPointManager 提供出生位置
-> CameraManager 刷新跟随相机和边界
-> SpecialMapCoordinator 初始化特殊地图状态
```

### 战斗链路

```text
玩家输入
-> PlayerController 当前状态执行 IAction
-> Attacker / Ammo / HitCheck 产生攻击检测
-> IDamageable 接收伤害
-> Health / DamageableHealth 改变血量
-> EventCenter 发送血量或 Boss 死亡事件
-> GamePanel / GameManager 响应结果
```

## 简历展示重点

最适合重点讲这 5 个：

1. `GraphCore`：自研节点图编辑器底层。
2. `StateMachine`：可视化状态机驱动角色行为。
3. `Dialogue + Quest + Condition`：对话、任务、条件系统联动。
4. `MapSystem`：配置驱动的地图连接和场景流转。
5. `Player 架构`：状态机、组件化能力、配置接口、形态策略。

背包、存档、UI、镜头、Boss 可以作为辅助证明，不需要全部细讲。

## 当前架构问题

- `GameManager` 职责偏重，已经承担开始游戏、存档、地图、玩家、Boss、UI 和结局流程。
- 单例和事件中心使用较多，调用方便，但依赖关系不够显性。
- 部分系统仍是“能跑优先”的结构，后续可以继续拆成更明确的运行态服务。

这不是致命问题，当前阶段可以接受。简历展示时重点讲“已经完成的系统联动”和“后续重构方向”，不要硬说架构已经完美。
