# 通用条件判断资源重构方案

## 计划说明

本计划要解决的问题是：`DialogueConditionSO` 这个名字把条件资源和对话系统绑定得太死。实际条件判断不一定只服务对话，也可能被机关交互、任务节点、地图事件等配置型逻辑复用。

本计划将 `DialogueConditionSO` 重构为通用 `ConditionSO`，并增加 `ConditionContext` 统一传入判断条件需要的外部上下文。执行后，对话分支、机关交互、任务节点等配置型判断，都可以复用同一套条件资源。

## 结论

- 新增通用条件基类 `ConditionSO`。
- 新增条件上下文 `ConditionContext`。
- 将现有 `DialogueConditionSO` 子类迁移为通用条件资源。
- 对话触发器继续使用条件数组，但类型从 `DialogueConditionSO[]` 改为 `ConditionSO[]`。
- `ConditionSO` 只负责配置型条件判断，不替代状态机 `EPredicate`。

## 最终结构

```text
ConditionSO
  -> AlwaysTrueConditionSO
  -> QuestStateConditionSO

  -> SpiderBossKilledConditionSO

  -> QuestDefinition
  -> Owner

```

核心类职责伪代码：

```csharp
public abstract class ConditionSO : ScriptableObject
{
    // 判断当前条件是否满足
    public abstract bool IsMet(ConditionContext context);
}
```

```csharp
public class ConditionContext
{
    // 当前判断关联的任务配置，可为空
    public QuestDefinitionSO QuestDefinition;

    // 当前条件判断的拥有者，例如 NPC、门、机关
    public GameObject Owner;

    // 触发本次判断的对象，例如玩家、交互者
    public GameObject Instigator;
}
```

```csharp
public static class ConditionUtility
{
    // 判断一组条件是否全部满足
    public static bool AreAllMet(ConditionSO[] conditions, ConditionContext context)
    {
        if (conditions == null || conditions.Length == 0)
        {
            return true;
        }

        foreach (ConditionSO condition in conditions)
        {
            if (condition == null)
            {
                continue;
            }

            if (!condition.IsMet(context))
            {
                return false;
            }
        }

        return true;
    }
}
```

```csharp
public class QuestStateConditionSO : ConditionSO
{
    // 期望的任务状态
    [SerializeField] private EQuestState _expectedState;

    // 判断传入任务的长期状态是否等于期望状态
    public override bool IsMet(ConditionContext context)
    {
        QuestDefinitionSO questDefinition = context?.QuestDefinition;

        if (questDefinition == null || string.IsNullOrWhiteSpace(questDefinition.QuestId))
        {
            Debug.LogError("任务状态条件缺少 QuestDefinitionSO 或 QuestId");
            return false;
        }

        return QuestManager.Instance.GetQuestState(questDefinition.QuestId) == _expectedState;
    }
}
```

调用方伪代码：

```csharp
public class DialogueNpcTrigger : MonoBehaviour
{
    // 判断对话配置的条件是否全部满足
    private bool CheckConditions(ConditionSO[] conditions, QuestDefinitionSO questDefinition)
    {
        var context = new ConditionContext
        {
            QuestDefinition = questDefinition,
            Owner = gameObject,
            Instigator = GameManager.Instance.Player.gameObject
        };

        return ConditionUtility.AreAllMet(conditions, context);
    }
}
```

## 改动清单

### 新增

- `Assets/Scripts/Conditions/ConditionSO.cs`
  - 定义通用条件资源基类。
  - 提供 `IsMet(ConditionContext context)`。
  - 不再绑定对话系统命名。

- `Assets/Scripts/Conditions/ConditionContext.cs`
  - 持有 `QuestDefinitionSO QuestDefinition`。
  - 持有 `GameObject Owner`。
  - 持有 `GameObject Instigator`。
  - 作为所有条件判断的统一上下文入口。

- `Assets/Scripts/Conditions/ConditionUtility.cs`
  - 作为条件数组的统一判断入口，避免每个调用方重复写遍历逻辑。
  - 提供 `AreAllMet(ConditionSO[] conditions, ConditionContext context)`。
  - 空数组默认返回 `true`。
  - 空条件跳过。

### 修改

- `Assets/PlayArk/DialogueSystem/Scripts/GraphEditor/Data/Info/DialogueConditionSO.cs`
  - 改名为 `ConditionSO`。
  - 移出对话系统命名空间。
  - 删除 `IsMet()` 和 `IsMet(QuestDefinitionSO questDefinition)` 的双重入口。
  - 统一改为 `IsMet(ConditionContext context)`。

- `Assets/Scripts/Dialogue/Conditions/QuestStateDialogueConditionSO.cs`
  - 改名为 `QuestStateConditionSO`。
  - 继承 `ConditionSO`。

  - 改名为 `QuestCompletableConditionSO`。
  - 继承 `ConditionSO`。

- `Assets/Scripts/Dialogue/Conditions/AlwaysTrueConditionSO.cs`
  - 继承 `ConditionSO`。

- `Assets/Scripts/Dialogue/Conditions/SpiderBossAliveConditionSO.cs`

## 执行顺序

1. 新增 `ConditionContext`。
2. 新增或改名 `ConditionSO`，统一 `IsMet(ConditionContext context)`。
3. 新增 `ConditionUtility.AreAllMet(...)`。
4. 迁移所有现有条件资源脚本继承关系和方法签名。
5. 修改 `DialogueNpcTrigger` 和 `DialogueOneTrigger` 的条件判断入口。
6. 用 `rg` 清理旧类型名和旧方法签名。
