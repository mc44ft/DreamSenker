# 移动与跳跃配置拆分重构方案

## 重构原因

当前 `IMoveConfig` 同时承担水平移动和跳跃配置，职责混在一起。

具体痛点：

- `Assets/Scripts/Character/Player/StateMachine/ConfigWrapper/IConfig.cs` 中，`IMoveConfig` 同时包含 `RunSpeed`、`JumpSpeed`、`JumpCount`、`GroundLayerMask`、`JumpGravityScale`、`FallGravityScale`。
- `Assets/Scripts/Character/Player/StateMachine/Components/Mover.cs` 同时负责水平移动、接地检测、跳跃次数、跳跃进入、下落重力和跳跃相关状态机条件判断。

不重构的问题：

- `Mover` 不能作为纯移动组件复用，因为它运行时还会执行跳跃和接地逻辑。
- 后续扩展移动或跳跃能力时，配置接口会继续膨胀。

## 重构目标

- `IMoveConfig` 只表示水平移动配置，只保留 `RunSpeed`。
- 补全 `IJumpConfig`，专门表示跳跃配置。
- 玩家形态配置同时实现 `IMoveConfig` 和 `IJumpConfig`。
- 水平移动逻辑继续由 `Mover` 负责。
- 跳跃、接地检测、跳跃次数、跳跃状态机谓词判断迁移到 `Jumper`。
- 状态机行为保持不变：玩家移动、跳跃、下落、接地判断的表现不变。

## 重构完成后的代码结构

```text
IConfig
  -> IMoveConfig
      -> RunSpeed
  -> IJumpConfig
      -> JumpSpeed
      -> JumpCount
      -> GroundLayerMask
      -> JumpGravityScale
      -> FallGravityScale

Mover : BaseComponent<IMoveConfig>
  -> Move()
  -> StopMove()
  -> SetMoveSpeedMultiplier()
  -> UpdateFace()

Jumper : BaseComponent<IJumpConfig>
  -> CheckIsGround()
  -> ResetJumpCounter()
  -> JumpEnterSetup()
  -> FallEnterSetup()
  -> Evaluate()
```

主要数据流：

```text
PlayerFormConfig
  -> IMoveConfig 注入 Mover
  -> IJumpConfig 注入 Jumper
  -> IHealthConfig 注入 PlayerHealth
  -> IAttackConfig 注入 Attacker
```

配置注入复用现有流程，不新增注入系统：

```text
FormStrategy.SwitchSetup()
  -> InjectionConfig(formConfig)
  -> GetComponents<IComponent>()
  -> component.InjectionConfigBase(config)
  -> BaseComponent<T> 判断 config is T
  -> 注入到对应组件
```

状态机谓词查询规则：

```text
StateTransitionEdge.Check()
  -> _controller.GetComponents<IPredicateEvaluator>()
  -> 逐个调用 Evaluate()
```

硬性前提：

- `Jumper` 必须和 `PlayerController`、`Mover`、`FormStrategy` 挂在同一个 GameObject 上。
- 代码不负责运行时 `AddComponent<Jumper>()` 兜底。
- `[RequireComponent(typeof(Jumper))]` 只能作为代码侧依赖声明，不代替 Prefab 挂载检查。
- 如果 `Jumper` 没挂在同一个 GameObject 上，状态机问不到 `Jumper.Evaluate()`。

标识符说明：

- `IMoveConfig`：移动配置接口，定义在 `Assets/Scripts/Character/Player/StateMachine/ConfigWrapper/IConfig.cs`。
- `IJumpConfig`：跳跃配置接口，定义在 `Assets/Scripts/Character/Player/StateMachine/ConfigWrapper/IConfig.cs`。
- `EPredicate.JumpCountNotZero`：状态机条件枚举值，表示跳跃次数是否不为 0。
- `EPredicate.VerticalSpeedNotNegative`：状态机条件枚举值，表示当前竖直速度是否大于 0。
- `EPredicate.Grounded`：状态机条件枚举值，表示角色是否接地。
- `EAction.JumpEnterSetup`：状态机动作枚举值，表示进入跳跃状态时执行的初始化动作。
- `EAction.FallEnterSetup`：状态机动作枚举值，表示进入下落状态时执行的初始化动作。

## 重构执行计划

### `Assets/Scripts/Character/Player/StateMachine/ConfigWrapper/IConfig.cs`

改动项：

- `IMoveConfig` 只保留 `RunSpeed`。
- `IJumpConfig` 改为继承 `IConfig`。
- `IJumpConfig` 增加 `JumpSpeed`、`JumpCount`、`GroundLayerMask`、`JumpGravityScale`、`FallGravityScale`。

改动前：

- `IMoveConfig` 同时包含移动和跳跃字段。
- `IJumpConfig` 是空接口，并且没有继承 `IConfig`。

改动后：

- `IMoveConfig` 只服务水平移动。
- `IJumpConfig` 只服务跳跃和接地检测。
- `BaseComponent<IJumpConfig>` 可以正常使用现有配置注入体系。

### `Assets/Scripts/Character/Player/StateMachine/Components/Mover.cs`

改动项：

- 删除 `_jumpCount`、`_previousIsGround`、`_isGround`。
- 删除 `CheckIsGround()`、`ResetJumpCounter()`、`JumpEnterSetup()`、`FallEnterSetup()`。
- 删除 `EPredicate.JumpCountNotZero`、`EPredicate.VerticalSpeedNotNegative`、`EPredicate.Grounded` 的判断。
- 保留 `Move()`、`StopMove()`、`SetMoveSpeedMultiplier()`、`UpdateFace()`。
- `Evaluate()` 不再处理跳跃相关谓词，不归 `Mover` 管的条件返回 `null`。

改动前：

- `Mover` 既负责水平移动，又负责跳跃和接地检测。

改动后：

- `Mover` 只负责水平移动和朝向。
- 跳跃相关判断不再混在移动组件里。

### `Assets/Scripts/Character/Player/StateMachine/Components/Jumper.cs`

改动项：

- 新增 `Jumper : BaseComponent<IJumpConfig>`。
- 持有 `IJumpConfig` 和 `Rigidbody2D`。
- 实现 `CheckIsGround()`、`ResetJumpCounter()`、`JumpEnterSetup()`、`FallEnterSetup()`。
- 实现 `Evaluate()`，处理 `EPredicate.JumpCountNotZero`、`EPredicate.VerticalSpeedNotNegative`、`EPredicate.Grounded`。
- `InjectionConfig(IJumpConfig config)` 复用 `BaseComponent<IJumpConfig>` 的现有注入路径。

改动前：

- 跳跃逻辑全部在 `Mover`。

改动后：

- 跳跃逻辑全部在 `Jumper`。
- 移动和跳跃能力在组件层面分开。

### `Assets/Scripts/Character/Player/StateMachine/FormStrategy/FormStrategy.cs`

改动项：

- 增加 `[RequireComponent(typeof(Jumper))]` 作为依赖声明。
- 增加 `protected Jumper _jumper`。
- `Awake()` 中获取 `Jumper`。
- `SwitchSetup()` 中把 `_mover.ResetJumpCounter()` 改为 `_jumper.ResetJumpCounter()`。
- 不在代码中运行时自动添加 `Jumper`。

改动前：

- 玩家形态只持有 `Mover`，跳跃动作也通过 `Mover` 执行。

改动后：

- 玩家形态同时持有 `Mover` 和 `Jumper`。
- 移动动作走 `Mover`，跳跃动作走 `Jumper`。

### `Assets/Scripts/Character/Player/StateMachine/FormStrategy/FormUnarmed.cs`

改动项：

- `EAction.JumpEnterSetup` 改为调用 `_jumper.JumpEnterSetup()`。
- `EAction.FallEnterSetup` 改为调用 `_jumper.FallEnterSetup()`。
- `EAction.Move` 和 `EAction.StopMove` 继续调用 `_mover`。

改动前：

- 移动和跳跃动作都调用 `_mover`。

改动后：

- 移动动作调用 `_mover`。
- 跳跃动作调用 `_jumper`。

### `Assets/Scripts/Character/Player/StateMachine/FormStrategy/FormSword.cs`

改动项：

- `EAction.JumpEnterSetup` 改为调用 `_jumper.JumpEnterSetup()`。
- `EAction.FallEnterSetup` 改为调用 `_jumper.FallEnterSetup()`。
- `EAction.Move` 和 `EAction.StopMove` 继续调用 `_mover`。

改动前：

- 移动和跳跃动作都调用 `_mover`。

改动后：

- 移动动作调用 `_mover`。
- 跳跃动作调用 `_jumper`。

### `Assets/Scripts/Data/ScriptableObjects/Character/Player/PlayerConfigSO.cs`

改动项：

- `PlayerFormConfig` 改为实现 `IMoveConfig, IJumpConfig, IHealthConfig, IAttackConfig`。
- `RunSpeed` 归属 `IMoveConfig`。
- `JumpSpeed`、`JumpCount`、`GroundLayerMask`、`JumpGravityScale`、`FallGravityScale` 归属 `IJumpConfig`。
- 不改已有跳跃字段名和字段类型。

改动前：

- `PlayerFormConfig` 通过 `IMoveConfig` 同时提供移动和跳跃数据。

改动后：

- `PlayerFormConfig` 分别向 `Mover` 和 `Jumper` 提供配置。
- 因为字段名和类型不变，已有玩家配置数据不应丢失。

### `Assets/Scripts/Character/Player/StateMachine/PlayerController.cs`

改动项：

- 增加 `[RequireComponent(typeof(Jumper))]` 作为依赖声明。
- 不直接处理跳跃逻辑。
- 不在代码中运行时自动添加 `Jumper`。

改动前：

- 玩家预期依赖 `Mover` 承担移动和跳跃。

改动后：

- 玩家代码侧声明需要 `Mover` 和 `Jumper` 两个功能组件。
- 玩家 Controller 仍只负责玩家初始化、形态切换和状态机动作入口。

## 重构计划执行顺序

1. 修改 `IConfig.cs`，先完成接口边界拆分。
2. 新增 `Jumper.cs`，把跳跃逻辑从 `Mover` 迁移出来。
3. 修改 `Mover.cs`，删除跳跃职责，只保留水平移动职责。
4. 修改 `PlayerConfigSO.cs`，让 `PlayerFormConfig` 同时实现 `IMoveConfig` 和 `IJumpConfig`。
5. 修改 `FormStrategy.cs`，让玩家形态同时持有 `Mover` 和 `Jumper`。
6. 修改 `FormUnarmed.cs` 和 `FormSword.cs`，把跳跃动作调用切到 `Jumper`。
7. 修改 `PlayerController.cs`，补充代码侧组件约束。
8. 用 `rg` 检查 `IMoveConfig` 是否只剩 `RunSpeed`。
9. 用 `rg` 检查跳跃相关动作和谓词是否只由 `Jumper` 承担。
10. 执行 `git diff --check`。
11. 检查 Unity Console Error 和 Exception。

## 注意项

- 不要在本次重构计划中修改 Prefab、Scene、ScriptableObject 资源、`.asset`、`.unity`、`.meta`。
- 新增 `Jumper.cs` 后，Unity 可能自动生成 `Jumper.cs.meta`；执行时只报告该变化，不手动创建或清理。
- 玩家 `PlayerFormConfig` 的跳跃字段不改名、不改类型，玩家配置数据不应丢失。
- `Jumper` 挂载由 Prefab 配置负责，本方案只保证代码在组件挂对的前提下跑通。
- 跳跃相关谓词如果没有任何组件处理，当前 `Condition.Check()` 会默认通过；所以 `Jumper.Evaluate()` 不能漏。
- 当前方案的好处是接口隔离和组件职责同时落地，不会只做表面接口拆分。
- 可以学到的知识点：接口隔离原则必须和组件职责一起看；否则接口拆了，组件仍然混在一起，复用问题不会真正解决。
