# 任务系统重构方案

## 计划说明

本计划要解决的问题是：当前任务逻辑还散在对话节点、`TaskPanel`、背包扣物品和存档字段里，发布任务、交付任务、判断任务状态没有统一入口。

执行后，任务长期状态统一由 `QuestManager` 读写，任务配置统一由 `QuestDefinitionSO` 描述，对话系统只负责在合适节点打开任务面板，任务面板只负责展示和触发接取 / 交付操作。

最终效果是：任务系统、对话系统、UI 面板之间职责分开，新增任务时不再继续硬编码“晨露梦核”这类单任务逻辑。

## 结论

本方案要完成“可接取任务 + 可交付任务”的基础任务链路。

- 新增任务配置 `QuestDefinitionSO`。
- 新增任务需求数据 `QuestItemRequirement`。
- 新增任务存档数据 `QuestRuntimeData`。
- 新增任务状态枚举 `EQuestState`。
- 新增 `QuestManager`，统一处理任务状态、可交付判断、接取、交付。
- 改造 `TaskPanel`，通过 `QuestDefinitionSO` 初始化显示内容。
- 新增 `DialogueExternalUIRunner`，协调对话节点和任务 UI。
- 改造 `DialogueNodeExternalUI`，不再通过 `EventCenter` 等外部 UI 完成事件。
- 新增任务状态对话条件和任务可交付对话条件。

## 最终结构

```text
GameManager
  -> QuestManager.SetupData(QuestDefinitionSO[], GameSaveData.QuestRuntimeDataList)

DialogueNpcTrigger / DialogueOneTrigger
  -> DialogueConditionSO[]
      -> QuestStateDialogueConditionSO
      -> QuestCompletableDialogueConditionSO
          -> QuestManager

DialogueNodeTaskPublish / DialogueNodeTaskDeliver
  -> DialogueNodeExternalUI
      -> DialogueManager.ExternalUIRunner
          -> TaskPanel
              -> QuestManager.StartQuest / CompleteQuest
```

数据流向：

```text
QuestDefinitionSO
  -> 描述任务固定配置

GameSaveData.QuestRuntimeDataList
  -> 保存任务长期状态

QuestManager
  -> 读取 QuestDefinitionSO
  -> 读写 QuestRuntimeData
  -> 查询 InventoryManager
```

失败策略：

```text
边界条件不满足：不执行，Debug.LogWarning
配置缺失 / 数据结构损坏：不执行，Debug.LogError
```

`QuestId`：

```text
类型：string
内容：GUID 字符串
来源：QuestDefinitionSO 创建后空则生成
用途：存档和运行时查询
```

## 改动清单

### 新增

- `Assets/Scripts/QuestSystem/Data/QuestDefinitionSO.cs`
  - 定义任务配置。
  - 持有只读显示的 `_questId`。
  - 持有任务标题、任务描述、目标描述。
  - 持有完成任务需要的物品列表。
  - `_questId` 为空时生成 GUID，已有值不自动改。

- `Assets/Scripts/QuestSystem/Data/QuestItemRequirement.cs`
  - 定义单个任务需求物品。
  - 字段包含 `EPackageItemType ItemType`。
  - 字段包含 `int Amount`。

- `Assets/Scripts/QuestSystem/Data/QuestRuntimeData.cs`
  - 定义任务运行时存档数据。
  - 字段包含 `QuestId`。
  - 字段包含 `EQuestState`。
  - 提供修改任务状态的方法。

- `Assets/Scripts/QuestSystem/EQuestState.cs`
  - `NotStarted`：任务未接取。
  - `Active`：任务进行中。
  - `Completed`：任务已完成。
  - 不添加 `ReadyToDeliver`，是否可交付由 `QuestManager.CanCompleteQuest` 动态判断。

- `Assets/Scripts/QuestSystem/QuestManager.cs`
  - 继承 `BaseManager<QuestManager>`。
  - 由 `GameManager` 注入任务配置列表和任务存档列表。
  - `GameSaveData.QuestRuntimeDataList` 是唯一任务状态数据源。
  - 提供 `StartQuest(string questId)`。
  - 提供 `CanCompleteQuest(string questId)`。
  - 提供 `CompleteQuest(string questId)`。
  - 提供 `GetQuestState(string questId)`。

- `Assets/Scripts/Dialogue/DialogueExternalUIRunner.cs`
  - 普通 C# 类，由 `DialogueManager` 持有。
  - 提供 `OpenTaskPanel(QuestDefinitionSO questDefinition, TaskPanel.E_PanelMode mode, Action<int> onFinished)`。
  - 负责打开 `TaskPanel`。
  - 负责在面板淡出完成后调用 `onFinished`。

- `Assets/PlayArk/DialogueSystem/Scripts/GraphEditor/Data/Nodes/OpenUiNodes/DialogueNodeTaskDeliver.cs`
  - 继承 `DialogueNodeExternalUI`。
  - 持有 `QuestDefinitionSO`。
  - 打开 `TaskPanel` 的交付模式。

- `Assets/Scripts/Dialogue/Conditions/QuestStateDialogueConditionSO.cs`
  - 继承 `DialogueConditionSO`。
  - 持有 `QuestDefinitionSO`。
  - 持有期望的 `EQuestState`。
  - 通过 `QuestManager.GetQuestState` 判断任务状态。

- `Assets/Scripts/Dialogue/Conditions/QuestCompletableDialogueConditionSO.cs`
  - 继承 `DialogueConditionSO`。
  - 持有 `QuestDefinitionSO`。
  - 持有期望的可交付结果。
  - 通过 `QuestManager.CanCompleteQuest` 判断是否可交付。

## 执行顺序

1. 新增任务数据结构：`EQuestState`、`QuestItemRequirement`、`QuestRuntimeData`、`QuestDefinitionSO`。
2. 在 `GameSaveData` 增加 `QuestRuntimeDataList`。
3. 新增 `QuestManager`，完成配置查询、状态读写、接取、可交付判断、交付。
4. 在 `GameManager` 注入任务配置和任务存档数据。
5. 新增 `DialogueExternalUIRunner`，先支持 `TaskPanel`。
6. 修改 `DialogueManager`，让它持有 Runner。
7. 修改 `TaskPanel`，改为由任务配置和回调驱动。
8. 修改 `DialogueNodeExternalUI`，移除外部 UI 完成事件监听。
9. 修改 `DialogueNodeTaskPublish`，接入 `QuestDefinitionSO` 和 Runner。
10. 新增 `DialogueNodeTaskDeliver`，支持任务交付面板。
11. 新增两个任务对话条件资源脚本。
12. 迁移 `BounsChoosePanel`、`RestoreHealthPanel` 的完成回调，清理旧事件链路。
13. 从 `GameManager`、`CustomEventArgs`、`E_EventType` 删除旧外部 UI 事件转发代码。
14. 用 `rg` 检查旧硬编码和旧事件是否清理干净。
