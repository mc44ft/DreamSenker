# 空洞骑士场景设计架构

> 本文档分析《空洞骑士》(Hollow Knight) 的场景管理系统设计，作为项目场景重构的参考。

---

## 一、核心设计理念

### Room-Based Loading（房间式加载）

空洞骑士采用**逐房间加载**的方式，这是 Metroidvania 游戏的经典设计。

```
整个游戏世界
├── Crossroads (十字路)
│   ├── Room_1_1
│   ├── Room_1_2
│   └── Room_1_3
├── Greenpath (苍绿之径)
│   ├── Room_2_1
│   └── Room_2_2
└── City of Tears (泪水之城)
    └── ...
```

**核心优势**：
- 单个房间加载时间极短（< 1秒）
- 内存占用小，只加载当前房间
- 便于内容管理和团队协作

## 二、关键设计特点

### 2.1 房间粒度的场景分割

| 设计要点 | 说明 |
|---------|------|
| **每房间一场景** | 每个 `.unity` 场景 = 一个游戏房间 |
| **小场景快速加载** | 单个房间加载时间极短（< 1秒） |
| **内存占用小** | 只加载当前房间 + 相邻房间预加载 |

```
玩家位置
    ├── 当前房间（已加载）
    ├── 相邻房间（预加载/准备中）
    └── 远处房间（未加载）
```

### 2.2 无缝过渡效果

空洞骑士的过渡效果非常巧妙：

```
玩家走到门口
    ↓
淡出 + 玩家动画（进入门）
    ↓
后台加载新房间（异步）
    ↓
淡入 + 玩家动画（从门出来）
    ↓
玩家获得控制权
```

**视觉技巧**：
- 黑屏时间很短（约 0.3-0.5 秒）
- 音效过渡掩盖加载
- 玩家动画延续（进门→出门）增加连续感

### 2.3 双向门系统

```
Room_A                         Room_B
┌──────────┐                  ┌──────────┐
│          │                  │          │
│    Door_A├───单向传送──────→┤Door_B    │
│          │                  │          │
│          │←───记录返回点────┤          │
└──────────┘                  └──────────┘
```

每个门记录：
- 目标场景名
- 目标门 ID
- 入场方向（从左/右/上/下进入）

### 2.4 场景数据持久化

```
RoomData（每个房间）
├── 敌人状态（存活/死亡）
├── 物品状态（已拾取/未拾取）
├── 开关状态（已激活/未激活）
├── 打破的墙壁
└── 宝箱状态
```

**关键设计**：
- 数据存储在全局管理器，不在场景内
- 场景加载时从管理器读取状态
- 离开场景时保存状态

### 2.5 预加载优化

```
场景边界检测
    ↓
玩家接近门 → 开始预加载相邻房间
    ↓
玩家触发门 → 场景已加载，直接切换
```

这就是为什么空洞骑士的切换非常快。

## 三、状态机视角的设计

```
GameStateMachine
│
├── MainMenuState
│   └── 主菜单场景
│
├── LoadingState
│   └── 存档加载、资源预热
│
├── GameplayState ──────────────────────┐
│   ├── ExplorationState（探索）         │
│   │   └── 玩家自由移动、房间内交互      │
│   │                                    │
│   ├── TransitionState（房间切换）      │
│   │   ├── 禁用玩家输入                 │
│   │   ├── 播放过渡动画                 │
│   │   ├── 异步加载新房间               │
│   │   ├── 卸载旧房间                   │
│   │   └── 恢复玩家控制                 │
│   │                                    │
│   ├── CombatState（战斗）              │
│   │   └── Boss 房间特殊处理            │
│   │                                    │
│   └── CutsceneState（过场）            │
│       └── 剧情动画播放                 │
│
└── PauseState
    └── 游戏暂停菜单
```

### 状态说明

| 状态 | 职责 | 进入条件 | 退出条件 |
|------|------|---------|---------|
| MainMenuState | 主菜单界面 | 游戏启动/返回主菜单 | 开始游戏/读档 |
| LoadingState | 资源加载 | 开始游戏/读档 | 加载完成 |
| ExplorationState | 房间内探索 | 进入房间后 | 触发门/进入战斗 |
| TransitionState | 房间切换 | 触发门 | 新房间加载完成 |
| CombatState | Boss战斗 | 进入Boss房间 | Boss战结束 |
| CutsceneState | 过场动画 | 触发剧情 | 动画结束 |
| PauseState | 暂停菜单 | 按暂停键 | 取消暂停 |

### 5.2 代码实现思路

```csharp
public class RoomTransitionManager : MonoBehaviour
{
    [SerializeField] private float fadeDuration = 0.3f;

    private GameStateMachine stateMachine;
    private PlayerController player;
    private RoomDataManager roomDataManager;

    public void TransitionToRoom(string targetScene, string targetDoorID)
    {
        StartCoroutine(TransitionCoroutine(targetScene, targetDoorID));
    }

    private IEnumerator TransitionCoroutine(string targetScene, string targetDoorID)
    {
        // 1. 进入过渡状态
        stateMachine.ChangeState(GameState.Transition);

        // 2. 禁用玩家输入
        player.DisableInput();

        // 3. 播放淡出动画
        yield return FadeOut(fadeDuration);

        // 4. 保存当前房间状态
        roomDataManager.SaveCurrentRoomState();

        // 5. 异步加载新场景
        var operation = SceneManager.LoadSceneAsync(targetScene, LoadSceneMode.Single);
        operation.allowSceneActivation = false;

        // 6. 等待加载完成
        while (operation.progress < 0.9f)
        {
            yield return null;
        }

        // 7. 激活新场景
        operation.allowSceneActivation = true;
        yield return operation;

        // 8. 恢复目标房间状态
        roomDataManager.RestoreRoomState(targetScene);

        // 9. 设置玩家位置
        var spawnPos = GetDoorSpawnPosition(targetDoorID);
        player.SetPosition(spawnPos);

        // 10. 播放淡入动画
        yield return FadeIn(fadeDuration);

        // 11. 恢复玩家输入
        player.EnableInput();

        // 12. 进入探索状态
        stateMachine.ChangeState(GameState.Exploration);
    }

    private Vector3 GetDoorSpawnPosition(string doorID)
    {
        // 根据门ID查找出生点位置
        var door = roomDataManager.GetDoor(doorID);
        return door.SpawnPosition;
    }

    private IEnumerator FadeOut(float duration)
    {
        // CanvasGroup alpha 1 -> 0
        yield return null;
    }

    private IEnumerator FadeIn(float duration)
    {
        // CanvasGroup alpha 0 -> 1
        yield return null;
    }
}
```

## 十、总结

空洞骑士场景系统的核心设计：

```
小房间 + 快速加载 + 流畅过渡 = 无缝体验
```

**不是复杂的技术，而是精细的设计。**

关键要点：
1. 场景粒度要小，单房间加载快
2. 过渡动画短，增加连续感
3. 数据分离，状态持久化
4. 预加载相邻房间，优化体验
5. 状态机管理游戏流程
