# OldMan 敌人创建架构方案

## 实现背景

具体痛点：

- `Assets/Scripts/Character/Enemy/OldMan/OldManController.cs` 已经继承 `StateMachineController`，也已经声明了 `Mover`、`Attacker`、`Health` 等依赖，但 `DoAction()` 为空，没有真正承接状态机动作。
- `Assets/Scripts/Character/Player/StateMachine/Components/Mover.cs` 已经改成 `Move(float horizontalValue)`，移动方向可以由外部传入，但 `OldMan` 还没有统一的 AI 方向来源。
- `Assets/Scripts/Character/Player/StateMachine/Components/Attacker.cs` 已经能通过 `Mover.FaceRight` 做攻击检测，但 `OldMan` 还缺少配置注入和攻击动作触发规划。
- `Assets/PlayArk/StateMachine/ActionState.cs` 会把 `EAction` 分发给同一个 GameObject 上启用的 `IAction`，但 `OldMan` 还没有专门的动作分发组件承接这些动作。
- `Assets/PlayArk/StateMachine/Utilities/Condition.cs` 会通过 `IPredicateEvaluator.Evaluate()` 查询状态切换条件，但 `OldMan` 还没有专门的 AI 组件提供敌人谓词。

不按这个结构实现的问题：

- 如果把 AI 判断、动作执行、配置注入、组件调用全部塞进 `OldManController`，Controller 会快速变成大而乱的脚本。
- `Mover`、`Attacker`、`Health` 这些功能组件虽然能复用，但 `OldMan` 侧没有稳定调用边界。
- 后续创建第二个地面近战敌人时，无法复用 `OldMan` 的结构经验。

## 实现目标

- 直接完善 `OldManController`，不新增新的敌人 Controller。
- `OldManController` 只负责配置入口、组件缓存和状态机生命周期。
- 新增 `OldManBrain`，只负责 AI 感知、移动方向和状态机谓词判断。
- 新增 `OldManActionDriver`，只负责接收状态机 `EAction` 并调用功能组件。
- `OldManConfig` 继续作为 OldMan 的配置数据类，并补充 AI 配置接口。
- `Mover` 继续只负责移动和朝向，不知道玩家、不知道敌人 AI。
- `Attacker` 继续只负责攻击检测，不知道状态机和 AI。
- 玩家已有行为保持不变。

## 实现完成后的代码结构

```text
OldManController : StateMachineController
  -> 持有 OldManConfigSO
  -> 初始化 OldManBrain / Mover / Attacker / Health / AnimationPlayer
  -> 注入 OldManConfig
  -> 继承状态机驱动能力

OldManBrain : MonoBehaviour, IPredicateEvaluator
  -> 感知玩家（通过 GameObject.FindWithTag("Player")）
  -> 计算 MoveDirection
  -> 判断 OldManCanSeePlayer / OldManInAttackRange / OldManLostPlayer

OldManActionDriver : MonoBehaviour, IAction
  -> 接收 EAction
  -> 调用 Mover.Move(oldManBrain.MoveDirection)
  -> 调用 Mover.StopMove()
  -> 调用 AnimationPlayer.PlayAnimation(...)
  -> 内部维护攻击冷却，限制攻击频率

Mover : BaseComponent<IMoveConfig>
  -> Move(float horizontalValue)
  -> StopMove()
  -> FaceRight

Attacker : BaseComponent<IAttackConfig>
  -> 通过动画事件触发攻击检测
  -> 通过 Mover.FaceRight 决定攻击方向
```

主要调用链：

```text
StateMachineController.Update()
  -> StateMachine.LogicUpdate()
  -> State.CheckTransitions()
  -> Condition.Check(_controller.GetComponents<IPredicateEvaluator>())
  -> OldManBrain.Evaluate(...)
  -> StateMachine.TransitionToState(...)
```

```text
ActionState.DoActions(...)
  -> _controller.GetComponents<IAction>()
  -> OldManActionDriver.DoAction(...)
  -> Mover / AnimationPlayer
```

主要数据流：

```text
OldManConfigSO.Config
  -> IMoveConfig 注入 Mover
  -> IAttackConfig 注入 Attacker
  -> IHealthConfig 注入 Health
  -> IEnemyAIConfig 注入 OldManBrain
```

标识符说明：

- `StateMachineController`：状态机控制器，定义在 `Assets/PlayArk/StateMachine/StateMachineController.cs`。
- `IAction`：状态机动作接收接口，定义在 `Assets/PlayArk/StateMachine/Utilities/IAction.cs`。
- `IPredicateEvaluator`：状态机条件判断接口，定义在 `Assets/PlayArk/StateMachine/Utilities/IPredicateEvaluator.cs`。
- `EAction.Move`：状态机动作枚举值，定义在 `Assets/PlayArk/StateMachine/Utilities/EAction.cs`。
- `EPredicate.OldManCanSeePlayer`：计划新增的状态机条件枚举值，表示 OldMan 是否发现玩家。
- `EPredicate.OldManInAttackRange`：计划新增的状态机条件枚举值，表示玩家是否进入 OldMan 攻击范围。
- `EPredicate.OldManLostPlayer`：计划新增的状态机条件枚举值，表示 OldMan 是否丢失玩家。
- `IEnemyAIConfig`：计划新增的敌人 AI 配置接口，继承 `IConfig`。

## 实现计划

### `Assets/Scripts/Character/Player/StateMachine/ConfigWrapper/IConfig.cs`

实现项：

- 新增 `IEnemyAIConfig : IConfig`。
- 增加 `DetectRange`、`AttackRange`、`LoseTargetRange` 只读属性。

当前状态：

- 配置接口只有移动、攻击、生命、跳跃相关接口。
- 敌人 AI 参数没有通用接口承接。

实现后：

- `OldManBrain` 只依赖 `IEnemyAIConfig`。
- `OldManConfig` 实现该接口后，可以直接注入给 `OldManBrain`。

### `Assets/PlayArk/StateMachine/Utilities/EAction.cs`

实现项：

- 新增 `Attack` 枚举值，用于触发攻击动作。

当前状态：

- `EAction` 已有 `StopMove`、`Move`、`PlayAnimation` 等枚举值。
- 缺少攻击相关的动作枚举。

实现后：

- `OldManActionDriver` 可以通过 `EAction.Attack` 接收攻击指令。

### `Assets/PlayArk/StateMachine/Utilities/EPredicate.cs`

实现项：

- 新增 `OldManCanSeePlayer`。
- 新增 `OldManInAttackRange`。
- 新增 `OldManLostPlayer`。

当前状态：

- 谓词主要覆盖玩家输入、动画、跳跃、受伤和死亡。
- `OldMan` 状态切换缺少语义明确的 AI 条件枚举。

实现后：

- `OldMan` 状态图可以直接使用 AI 谓词做转换条件。
- 谓词判断由 `OldManBrain.Evaluate()` 承接。

### `Assets/Scripts/Data/ScriptableObjects/Character/Enemy/OldManConfigSO.cs`

实现项：

- 让 `OldManConfig` 增加 `IEnemyAIConfig` 实现。
- 增加 `_detectRange`、`_attackRange`、`_loseTargetRange` 序列化字段。
- 增加 `DetectRange`、`AttackRange`、`LoseTargetRange` 只读属性。

当前状态：

- `OldManConfig` 只实现 `IMoveConfig`、`IAttackConfig`、`IHealthConfig`。
- `OldMan` 的 AI 参数没有配置入口。

实现后：

- `OldManConfig` 同时提供移动、攻击、生命、AI 参数。
- 功能组件和 AI 组件都只依赖接口，不依赖具体字段。

### `Assets/Scripts/Character/Enemy/OldMan/OldManBrain.cs`

实现项：

- 新增 `OldManBrain : MonoBehaviour, IPredicateEvaluator`。
- 持有 `IEnemyAIConfig`。
- 通过 `GameObject.FindWithTag("Player")` 缓存玩家 `Transform`。
- 暴露 `MoveDirection`。
- 实现 `InjectionConfig(IEnemyAIConfig config)`。
- 实现 `Evaluate(EPredicate predicate, string[] parameters)`。
- 处理 `EPredicate.OldManCanSeePlayer`、`EPredicate.OldManInAttackRange`、`EPredicate.OldManLostPlayer`。

当前状态：

- `OldMan` 没有独立 AI 判断组件。

实现后：

- `OldMan` 状态切换只向 `OldManBrain` 查询判断结果。
- 移动方向由 `OldManBrain.MoveDirection` 提供给动作执行层。

### `Assets/Scripts/Character/Enemy/OldMan/OldManActionDriver.cs`

实现项：

- 新增 `OldManActionDriver : MonoBehaviour, IAction`。
- 持有 `OldManBrain`、`Mover`、`AnimationPlayer`。
- 实现 `DoAction(EAction action, string[] parameters)`。
- `EAction.Move` 调用 `_mover.Move(_brain.MoveDirection)`。
- `EAction.StopMove` 调用 `_mover.StopMove()`。
- `EAction.PlayAnimation` 调用 `_animationPlayer.PlayAnimation(parameters[0])`。
- `EAction.Attack` 内部维护攻击冷却，冷却结束才执行攻击。

当前状态：

- `OldManController.DoAction()` 为空。
- `OldMan` 没有独立动作分发脚本。

实现后：

- 状态机动作全部由 `OldManActionDriver` 翻译成组件调用。
- `OldManController` 不承担具体动作执行。

### `Assets/Scripts/Character/Enemy/OldMan/OldManController.cs`

实现项：

- 移除 `IAction` 实现。
- 删除空的 `DoAction(EAction action, string[] parameters)`。
- 增加 `[RequireComponent(typeof(OldManBrain))]`。
- 增加 `[RequireComponent(typeof(OldManActionDriver))]`。
- 保留 `OldManConfigSO _config`。
- 在 `Awake()` 中缓存 `Mover`、`Attacker`、`Health`、`AnimationPlayer`、`OldManBrain`。
- 把 `_config.Config` 注入到 `Mover`、`Attacker`、`Health`、`OldManBrain`。

当前状态：

- `OldManController` 既是状态机控制器，又占着 `IAction` 入口，但没有执行任何动作。

实现后：

- `OldManController` 只负责配置入口和组件装配。
- 状态机驱动继续复用 `StateMachineController`。
- 动作执行转交 `OldManActionDriver`。

### `Assets/Scripts/Character/Player/StateMachine/Components/Mover.cs`

实现项：

- 保留 `Move(float horizontalValue)` 的方向参数。
- 保留 `UpdateFace(float horizontalValue)` 只由传入方向驱动。
- 增加 `FaceTo(float horizontalDirection)`，供 `OldMan` 攻击状态原地朝向玩家使用。

当前状态：

- `Mover` 已经不再直接读 `InputManager` 执行移动。
- 但没有公开的原地转身方法。

实现后：

- `OldMan` 追击时用 `MoveDirection` 移动并转身。
- `OldMan` 攻击前不移动时，也可以通过 `FaceTo()` 朝向玩家。

## 实现顺序

1. 先改 `IConfig.cs`，补上 `IEnemyAIConfig`，让 AI 配置有接口边界。
2. 再改 `EAction.cs`，新增 `Attack` 枚举值。
3. 改 `EPredicate.cs`，补上 `OldMan` 状态切换所需谓词。
4. 修改 `OldManConfigSO.cs`，让 `OldManConfig` 提供 AI 参数。
5. 新增 `OldManBrain.cs`，完成玩家感知、移动方向、谓词判断。
6. 新增 `OldManActionDriver.cs`，把状态机动作转成组件调用。
7. 修改 `OldManController.cs`，只保留配置注入和组件装配。
8. 最后补 `Mover.FaceTo(float horizontalDirection)`，解决攻击状态原地朝向问题。

## 注意项

- 本方案只规划代码实现，不规划 Prefab、Scene、StateMachine 图、ScriptableObject 资产和 `.meta` 修改。
- `OldMan` GameObject 是否挂齐脚本、状态机图怎么连、动画事件是否配置，由 Unity 资产侧处理，不放进本次代码执行计划。
- `OldManBrain` 不直接调用 `Mover` 和 `Attacker`，否则 AI 判断层和执行层会混在一起。
- `OldManActionDriver` 不做感知和距离判断，否则动作层会变成第二个 AI。
- `OldManController` 不写具体 AI 行为，否则 Controller 会变成大而乱的脚本。
- 更简单的替代方案是把 `OldManBrain` 和 `OldManActionDriver` 的逻辑都写进 `OldManController`；当前不推荐，因为后续敌人复用价值很低。
