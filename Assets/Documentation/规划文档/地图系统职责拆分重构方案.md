# 地图系统职责拆分重构方案

## 阶段定义

本方案只针对第一阶段。

第一阶段含义：

- 只把地图系统从 `GameManager` 中拆出。
- 只处理地图查询、地图切换、玩家切图落点、特殊地图进入逻辑。
- `GameManager` 暂时保留外部入口，`ChangeMap()`、`TeleportMap()` 等方法只改成薄转发。
- 不重构 Boss、对话、存档、UI、相机系统的整体架构。

第二阶段要做的事：

- 从 `GameManager` 中继续拆出 Boss 流程，例如 `OnGameBossDead()`。
- 从 `GameManager` 中继续拆出对话外部 UI 入口，例如 `OnDialogueNodeShowPanel()`。
- 从 `GameManager` 中继续拆出存档和游戏初始化流程，例如 `LoadGame()`、`InitializeGame()`、`SaveDataAll()`。
- 评估是否引入更明确的运行时状态机，例如主菜单、加载地图、探索、对话、Boss 战、过场状态。

本方案不执行第二阶段内容。

## 重构原因

`Assets/Scripts/Managers/GameManager.cs` 已经承担过多职责，地图系统是当前最该先拆的一块。

当前具体痛点：

- `GameManager` 同时负责地图查询、场景加载、玩家传送、特殊地图逻辑、相机参数同步、存档字段更新。
- `ChangeMap(string pointGuid)` 和 `TeleportMap(string mapId, string teleportID = "")` 直接操作 `GameSaveData.CurrentMapId`、`GameSaveData.PreviousMapId`、`SpawnPointManager`、`MapLinkPointManager`、`SceneTransition`、`CameraManager`、`PlayerMirrorEffect`。
- `GetRequiredMapById`、`GetRequiredMapBySceneName`、`TryFindCurrentMap`、`TryFindMapBySceneName`、`TryGetCurrentMap...Camera...` 都是地图查询职责，但现在塞在 `GameManager` 里。
- `SpecialMapInitialize()` 混合了 CaveMap、MirrorMap1、MirrorMap2 的表现逻辑、音乐逻辑、玩家形态逻辑和存档字段更新。

不重构会带来的问题：

- 每次新增地图配置字段，都要继续往 `GameManager` 塞查询方法。
- 每次改切图流程，都容易误伤玩家生成、UI、Boss、对话、相机。
- `GameManager` 会继续变成全项目改动热点，后续拆任何系统都会变难。

## 重构目标

重构完成后要消除的问题：

- `GameManager` 不再直接承载地图查询细节。
- `GameManager` 不再直接编排完整切图流程。
- 特殊地图逻辑从 `GameManager` 的主流程里移出。
- 相机需要的地图参数由地图查询服务提供，不再让 `GameManager` 承担字段转发职责。

行为保持不变：

- 外部仍可调用 `GameManager.Instance.ChangeMap(pointGuid)`。
- 外部仍可调用 `GameManager.Instance.TeleportMap(mapId, teleportID)`。
- `MapTransitionTrigger` 仍然通过 `MapLinkPoint.PointGuid` 触发换图。
- `MapConnectionDatabaseSO` 仍然是地图连接数据来源。
- `MapRegistrySO` 仍然是地图定义清单来源。
- `MapDefinitionSO` 继续保存地图 ID、场景名、玩家阴影、相机参数等配置。

职责重新归属：

- 地图配置查询归 `MapRuntimeQuery`。
- 地图切换流程归 `MapFlowController`。
- 特殊地图初始化归 `SpecialMapCoordinator`。
- `GameManager` 保留玩家、存档、全局事件入口，并作为旧调用的 facade。

第一阶段 `GameManager` 明确保留的入口：

- `ChangeMap(string pointGuid)`：保留公开方法，只转发到 `MapFlowController.ChangeMap(pointGuid)`。
- `TeleportMap(string mapId, string teleportID = "")`：保留公开方法，只转发到 `MapFlowController.TeleportMap(mapId, teleportID)`。
- `GetMapIdFromEnum(EMapSceneName sceneName)`：保留公开方法，内部转发到 `MapRuntimeQuery`。
- `TryGetCurrentMapFollowCameraOrthoSize(out float orthoSize)`：保留公开方法，内部转发到 `MapRuntimeQuery`。
- `TryGetCurrentMapBossCameraOrthoSize(out float orthoSize)`：保留公开方法，内部转发到 `MapRuntimeQuery`。
- `TryGetCurrentMapDialogueCameraSettings(out float orthoSize, out float offsetY)`：保留公开方法，内部转发到 `MapRuntimeQuery`。

第一阶段 `GameManager` 不拆的内容：

- `OnGameBossDead()` 保留在 `GameManager`。
- `OnDialogueNodeShowPanel()` 保留在 `GameManager`。
- `LoadGame()`、`InitializeGame()`、`SaveDataAll()` 保留在 `GameManager`。
- `Player`、`GameSaveData` 的持有权保留在 `GameManager`。

## 新增类的生命周期形态

`MapRuntimeQuery`、`MapFlowController`、`SpecialMapCoordinator` 均为非单例纯 C# 类，由 `GameManager` 在 `InitializeGame()` 中直接 `new` 出来并持有字段引用，依赖通过构造函数注入。它们随 `GameManager`（DontDestroyOnLoad）一起存活到应用退出，无需手动管理释放。

`MapFlowController` 的依赖（MapRuntimeQuery、SceneTransition、SpawnPointManager、MapLinkPointManager、CameraManager、SpecialMapCoordinator）全部由 `GameManager` 在 `InitializeGame()` 中注入。`InitializeGame()` 在场景已加载、所有 MonoBehaviour 的 Awake() 已执行完毕后才调用，此时所有单例（CameraManager）和场景内对象（SpawnPointManager、MapLinkPointManager、SceneTransition）均已就绪，不存在依赖未初始化的问题。

## 异步场景加载的流程控制

`MapFlowController.LoadMap()` 内部调用 `SceneTransition` 进行异步场景加载，当前暂不处理加载期间重复触发 `ChangeMap()` 等并发调用问题。现有流程在时序上未出现相关 bug，等实际遇到时再按需补充（如 `_isLoading` 标志位）。

## SpecialMapCoordinator 的扩展策略

当前只做搬家，保持现有 switch 分支结构不变。新增特殊地图时继续加 if/switch 分支即可，后续再考虑是否改为策略模式或查表。

`SpecialMapCoordinator` 的职责边界：

- 只负责特殊地图进入后的表现和状态修正。
- 可以处理特殊地图音乐、UI、玩家镜像表现、玩家形态切换、特殊存档字段更新。
- 不负责场景加载。
- 不负责玩家生成。
- 不负责地图连接查询。
- 不负责普通地图切换。
- 不负责相机参数查询。

## 重构完成后的代码结构

目标结构：

```text
GameManager
  -> MapFlowController
      -> MapRuntimeQuery
      -> SceneTransition
      -> SpawnPointManager
      -> MapLinkPointManager
      -> CameraManager
      -> SpecialMapCoordinator

CameraManager
  -> GameManager facade
      -> MapRuntimeQuery

SpecialMapCoordinator
  -> GameSaveData
  -> PlayerController
  -> PlayerMirrorEffect
  -> UIManager / AudioManager / EventCenter
```

关键类职责：

- `GameManager`
  - 保留 `LoadGame()`、`SaveDataAll()`、`Player`、`GameSaveData`、Boss 死亡事件入口。
  - 对外保留 `ChangeMap()`、`TeleportMap()`、`GetMapIdFromEnum()`、`CheckGameCondition()`。
  - 内部把地图调用转交给地图系统类。
  - 第一阶段继续作为 `CameraManager` 获取地图相机参数的 facade。

- `MapRuntimeQuery`
  - 持有 `MapConnectionDatabaseSO`。
  - 负责 `MapDefinitionSO` 查询。
  - 负责当前地图相机参数查询。
  - 负责 `MapEndpointData` 连接对端查询。

- `MapFlowController`
  - 负责普通地图切换和传送地图。
  - 负责切图前清理 `SpawnPointManager` 和 `MapLinkPointManager`。
  - 负责切图后移动玩家并刷新相机。
  - 负责更新 `GameSaveData.CurrentMapId` 和 `GameSaveData.PreviousMapId`。

- `SpecialMapCoordinator`
  - 负责 `SpecialMapInitialize()` 里的 CaveMap、MirrorMap1、MirrorMap2 逻辑。
  - 负责特殊地图音乐、UI、镜像表现、玩家形态变化。

非显然标识符说明：

- `MapDefinitionSO`：地图配置 ScriptableObject，定义在 `Assets/Scripts/MapSystem/Data/MapDefinitionSO.cs`。
- `MapConnectionDatabaseSO`：地图连接数据库 ScriptableObject，定义在 `Assets/Scripts/MapSystem/Data/MapConnectionDatabaseSO.cs`。
- `MapRegistrySO`：地图配置清单 ScriptableObject，定义在 `Assets/Scripts/MapSystem/Data/MapRegistrySO.cs`。
- `MapEndpointData`：地图连接端点数据结构，定义在 `MapConnectionDatabaseSO.cs`。
- `MapLinkPoint.PointGuid`：地图连接点唯一 ID，定义在 `Assets/Scripts/MapSystem/MapLinkPoint.cs`。
- `EMapSceneName`：地图场景枚举，当前由 `GameManager.GetSceneNameFromEnum()` 使用。

## 重构执行计划

### `Assets/Scripts/MapSystem/MapRuntimeQuery.cs`

改动项：

- 新增脚本。
- 构造时接收 `MapConnectionDatabaseSO`。
- 提供地图查询、连接查询、相机参数查询。

改动前：

- `GameManager` 直接调用 `ConnectionDatabase.MapRegistry.AllMaps`。
- 地图找不到时由 `GameManager` 私有方法抛异常。
- 相机参数查询散落在 `GameManager`。

改动后：

- `MapRuntimeQuery.GetRequiredMapById(string mapId)` 返回指定 `MapDefinitionSO`。
- `MapRuntimeQuery.GetRequiredMapBySceneName(string sceneName)` 返回指定 `MapDefinitionSO`。
- `MapRuntimeQuery.TryFindMapBySceneName(string sceneName, out MapDefinitionSO map)` 用于非地图场景判断。
- `MapRuntimeQuery.TryFindCurrentMap(GameSaveData saveData, out MapDefinitionSO map)` 用于当前地图查询。
- `MapRuntimeQuery.GetOtherEndpointOrThrow(string currentMapId, string pointGuid)` 包装 `MapConnectionDatabaseSO.TryGetOtherEndpoint()`。
- `MapRuntimeQuery.TryGetCurrentMapFollowCameraOrthoSize(...)`、`TryGetCurrentMapBossCameraOrthoSize(...)`、`TryGetCurrentMapDialogueCameraSettings(...)` 统一提供相机参数。

### `Assets/Scripts/MapSystem/MapFlowController.cs`

改动项：

- 新增脚本。
- 承接 `ChangeMap()`、`TeleportMap()`、`LoadMap()`、`LoadMapScene()`、`ChangePlayerPosition()`。
- 通过构造参数或初始化方法接收运行时依赖。

改动前：

- `GameManager.ChangeMap()` 直接完成：清理点位缓存、查连接、更新存档、加载场景、移动玩家、更新阴影、执行特殊地图逻辑。
- `GameManager.TeleportMap()` 有一套类似流程，和 `ChangeMap()` 重复。

改动后：

- `MapFlowController.ChangeMap(string pointGuid)` 负责普通连接换图。
- `MapFlowController.TeleportMap(string mapId, string teleportID)` 负责指定地图传送。
- `MapFlowController.LoadMap(MapDefinitionSO mapDefinition, Action onFinished)` 负责地图场景加载。
- `MapFlowController.ChangePlayerPosition(Vector3 position)` 负责玩家瞬移和 `CameraManager.RefreshFollowCameraAfterPlayerWarp()`。
- `GameManager.ChangeMap()` 只转发到 `MapFlowController.ChangeMap()`。
- `GameManager.TeleportMap()` 只转发到 `MapFlowController.TeleportMap()`。

### `Assets/Scripts/MapSystem/SpecialMapCoordinator.cs`

改动项：

- 新增脚本。
- 承接 `GameManager.SpecialMapInitialize()` 的特殊地图处理。

改动前：

- `GameManager.SpecialMapInitialize()` 直接判断 CaveMap、MirrorMap1、MirrorMap2。
- 该方法直接触发 `EventCenter`、`AudioManager`、`UIManager`、`Player.SwitchForm()`、`PlayerMirrorEffect`。

改动后：

- `SpecialMapCoordinator.InitializeCurrentMap(...)` 接收 `GameSaveData`、`PlayerController`、`PlayerMirrorEffect`、`MapRuntimeQuery`。
- 内部保留当前特殊地图规则，但从 `GameManager` 移出。
- `MapFlowController` 在切图后调用 `SpecialMapCoordinator.InitializeCurrentMap(...)`。
- `GameManager.InitializeGame()` 在玩家初始化后调用同一个入口。
- 不调用 `SceneTransition`。
- 不调用 `MapConnectionDatabaseSO.TryGetOtherEndpoint()`。
- 不移动玩家位置。
- 不读写 `CameraManager` 相机参数。

### `Assets/Scripts/Managers/GameManager.cs`

改动项：

- 删除地图查询私有方法的实现，改为调用 `MapRuntimeQuery`。
- 删除完整切图流程实现，改为调用 `MapFlowController`。
- 删除 `SpecialMapInitialize()` 具体逻辑，改为调用 `SpecialMapCoordinator`。
- 保留外部调用入口，降低改动面。

改动前：

- `GameManager` 直接拥有地图系统几乎所有运行时流程。
- `CameraManager` 需要地图相机参数时调用 `GameManager.TryGetCurrentMap...()`。

改动后：

- `GameManager` 在 `Awake()` 或 `InitializeGame()` 前后初始化 `_mapRuntimeQuery`、`_mapFlowController`、`_specialMapCoordinator`。
- `GameManager.ChangeMap()`、`GameManager.TeleportMap()` 只保留兼容转发。
- `GameManager.GetMapIdFromEnum()` 保留为兼容接口，内部转发到 `MapRuntimeQuery`。
- `GameManager.TryGetCurrentMapFollowCameraOrthoSize()` 保留为兼容接口，内部转发到 `MapRuntimeQuery`。
- `GameManager.TryGetCurrentMapBossCameraOrthoSize()` 保留为兼容接口，内部转发到 `MapRuntimeQuery`。
- `GameManager.TryGetCurrentMapDialogueCameraSettings()` 保留为兼容接口，内部转发到 `MapRuntimeQuery`。
- `GameManager.OnGameBossDead()`、`OnDialogueNodeShowPanel()`、`LoadGame()`、`InitializeGame()`、`SaveDataAll()` 第一阶段不抽离。

### `Assets/Scripts/CameraSystem/CameraManager.cs`

改动项：

- 第一阶段不改 `CameraManager` 的依赖方向。
- 继续通过 `GameManager` facade 读取当前地图相机参数。

改动前：

- `CameraManager` 通过 `GameManager.Instance.TryGetCurrentMapBossCameraOrthoSize(...)` 获取 Boss 镜头配置。
- `CameraManager` 通过 `GameManager.Instance.TryGetCurrentMapDialogueCameraSettings(...)` 获取对话镜头配置。

改动后：

- 仍然调用 `GameManager.Instance.TryGetCurrentMapBossCameraOrthoSize(...)`。
- 仍然调用 `GameManager.Instance.TryGetCurrentMapDialogueCameraSettings(...)`。
- `GameManager` 内部把这些调用转发给 `MapRuntimeQuery`。
- 不让 `CameraManager` 直接依赖 `MapRuntimeQuery`。
- 不在第一阶段引入完整 DI 框架，避免牵出相机系统重排。

### `Assets/Scripts/MapSystem/MapTransitionTrigger.cs`

改动项：

- 保持外部行为不变。
- 第一阶段不强制修改。

改动前：

- 触发后调用 `GameManager.Instance.ChangeMap(_mapLinkPoint.PointGuid)`。

改动后：

- 第一阶段仍调用 `GameManager.Instance.ChangeMap(...)`。
- 后续如果要减少 `GameManager` 入口，再改为 `MapFlowController` 的统一入口。

## 重构计划执行顺序

1. 新建 `MapRuntimeQuery`，只迁移纯查询逻辑，不改切图流程。
2. 让 `GameManager` 内部查询方法转发到 `MapRuntimeQuery`，验证当前地图参数、地图 ID、连接查询不变。
3. 新建 `SpecialMapCoordinator`，迁移 `SpecialMapInitialize()` 逻辑。
4. 让 `GameManager.SpecialMapInitialize()` 暂时转发到 `SpecialMapCoordinator`，验证 CaveMap、MirrorMap1、MirrorMap2 行为不变。
5. 新建 `MapFlowController`，迁移 `LoadMap()`、`LoadMapScene()`、`ChangePlayerPosition()`。
6. 迁移 `ChangeMap()` 和 `TeleportMap()` 到 `MapFlowController`。
7. `GameManager.ChangeMap()` 和 `GameManager.TeleportMap()` 改成薄转发，验证 `MapTransitionTrigger` 不需要修改。
8. 保持 `CameraManager` 调用 `GameManager` facade，不让相机系统直接依赖 `MapRuntimeQuery`。
9. 用 `rg` 检查 `GameManager` 中剩余的 `MapDefinitionSO`、`MapConnectionDatabaseSO`、`MapLinkPointManager`、`SpawnPointManager` 直接引用，确认地图职责已经移出。

## 验证标准

代码检查：

- `rg "GetRequiredMapById|GetRequiredMapBySceneName|TryFindCurrentMap|TryFindMapBySceneName|GetOtherEndpointOrThrow" Assets/Scripts/Managers/GameManager.cs` 不应再出现这些方法实现。
- `rg "MapDefinitionSO|MapConnectionDatabaseSO|MapLinkPointManager|SpawnPointManager" Assets/Scripts/Managers/GameManager.cs` 只允许出现在字段声明、初始化注入或 facade 转发中，不允许出现完整地图流程逻辑。
- `rg "TryGetCurrentMapFollowCameraOrthoSize|TryGetCurrentMapBossCameraOrthoSize|TryGetCurrentMapDialogueCameraSettings" Assets/Scripts/CameraSystem/CameraManager.cs` 仍应显示 `CameraManager` 通过 `GameManager` facade 读取地图相机配置。
- `rg "SceneTransition|ChangePlayerPosition|GetOtherEndpointOrThrow" Assets/Scripts/MapSystem/SpecialMapCoordinator.cs` 不应有结果。

功能验证：

- 从一个普通 `MapLinkPoint` 进入下一个地图，玩家能出现在目标 `PointGuid` 对应位置。
- 从下一个地图通过连接点回到原地图，玩家能回到对应连接点位置。
- `TeleportMap(mapId, teleportID)` 能传送到指定地图和指定出生点。
- `TeleportMap(mapId)` 不传 `teleportID` 时，仍使用 `ESpawnType.TeleportPoint` 对应出生点。
- 切图后 Follow VCam 不再因玩家瞬移产生偏移。
- 进入 Registry 中的地图后，Follow VCam 使用当前 `MapDefinitionSO.FollowCameraOrthoSize`。
- 进入 Boss 战时，Follow VCam 使用当前 `MapDefinitionSO.FollowCameraBossOrthoSize`。
- 退出 Boss 战时，Follow VCam 恢复当前 `MapDefinitionSO.FollowCameraOrthoSize`。
- 进入对话时，Dialogue VCam 使用当前 `MapDefinitionSO.DialogueCameraOrthoSize` 和 `DialogueCameraOffsetY`。
- 退出对话时，Dialogue VCam 恢复初始配置。
- MirrorMap1 进入后音乐、GamePanel 隐藏、玩家镜像表现不变。
- MirrorMap2 进入后玩家形态切换逻辑不变。
- CaveMap 中蜘蛛已死亡后的 `Game_BossKeepDead` 事件和从 MirrorMap2 返回后的奖励逻辑不变。

基础验证：

- `git diff --check` 通过。
- Unity Console 最近无 Error。
- 不运行 `dotnet build Assembly-CSharp.csproj`，除非用户明确要求。

## 注意项

- 本方案只安排脚本改动，不安排修改 Prefab、Scene、ScriptableObject、`.asset`、`.unity`、`.meta`。
- 如果新增脚本导致 Unity 自动生成 `.meta`，只报告，不手动处理。
- 不删除或移动现有脚本，除非执行前单独确认 `.cs.meta` 怎么处理。
- 第一阶段保留 `GameManager` facade 是为了降低调用面风险，不是最终架构。
- 不建议现在直接上完整状态机。当前更痛的是地图系统职责过重，先拆地图流转比全局状态机更划算。
- 当前方案适合学习的点：Facade 兼容旧入口、查询服务抽离、流程控制器拆分、特殊规则协调器拆分。
