# 健康系统实现方案

## 结论

当前项目的健康系统分成两套：

- `Health`：通用血量组件，主要给怪物、Boss、蜘蛛丝等对象使用。
- `PlayerHealth -> NewHealth`：玩家专用血量组件，接入了玩家状态机、受击无敌、击退、UI事件。

伤害入口统一靠 `IDamageable.TakeDamage(int damage, Vector2 attackDirection)`。攻击方不直接关心目标是玩家、怪物还是可破坏物，只要目标实现了 `IDamageable` 就能造成伤害。

---

## 核心接口

### `IDamageable`

位置：`Assets/Scripts/Health/IDamageable.cs`

所有“可以被打”的对象都实现这个接口。

核心方法：

- `TakeDamage(int damage, Vector2 attackDirection)`：承受伤害，`attackDirection` 用于击退方向。
- `GetPosition()`：返回对象世界坐标，主要给选中、索敌、镜像攻击逻辑使用。
- `Select()` / `Deselect()`：被镜像攻击选中或取消选中时的表现入口。

### `ITouchDamageable`

位置：`Assets/Scripts/Health/ITouchDamageable.cs`

所有“碰到玩家会造成伤害”的怪物实现这个接口。

核心方法：

- `GetTouchDamage()`：返回触碰伤害值。

`TouchHit` 会从怪物根节点拿到 `ITouchDamageable`，再对玩家身上的 `IDamageable` 调用 `TakeDamage`。

---

## 通用血量组件 `Health`

位置：`Assets/Scripts/Health/Health.cs`

`Health` 是最基础的血量容器，只负责记录血量和死亡标记。

它持有：

- `MaxHealthAmount`：最大血量。
- `CurrentHealthAmount`：当前血量。
- `IsDead`：是否死亡。

主要流程：

```csharp
Initialize(max, current)
ApplyDamage(damage)
RestoreHealth(amount)
```

实现特点：

- `Initialize` 会重置 `IsDead = false`。
- `ApplyDamage` 直接扣血，血量小于等于 0 时调用 `Death()`。
- `RestoreHealth` 会限制不超过最大血量。
- 没有无敌、击退、事件通知、死亡动画。

所以 `Health` 不负责表现，也不负责销毁对象。怪物自己在 `TakeDamage` 里根据 `Health.IsDead` 决定下一步。

## 玩家血量组件

### 继承关系

```text
PlayerHealth
  -> NewHealth
      -> BaseComponent<IHealthConfig>
      -> IDamageable
```

位置：

- `Assets/Scripts/Character/Player/StateMachine/Components/NewHealth.cs`
- `Assets/Scripts/Character/Player/StateMachine/Components/PlayerHealth.cs`

`NewHealth` 是玩家血量主逻辑，`PlayerHealth` 目前只补了动画事件里的受击表现。

### 玩家血量初始化

玩家形态切换时，`FormStrategy.SwitchSetup()` 会初始化血量：

```csharp
_health.Initialize(_formConfig.MaxHealthAmount, _playerSaveData.CurrentHealth);
```

也就是说：

- 最大血量来自当前形态的 `PlayerFormConfig.MaxHealthAmount`。
- 当前血量来自 `PlayerSaveData.CurrentHealth`。
- 形态配置通过 `IHealthConfig` 注入给 `PlayerHealth`，用于受击击退力度、顿帧时间等参数。

### 玩家受击流程

外部攻击玩家时，最终会调用：

```csharp
PlayerHealth.TakeDamage(damage, attackDirection)
```

流程：

1. 如果还在无敌时间内，直接 return。
2. 触发 `_onDamageTaken`，让状态机条件能感知“玩家受伤了”。
3. 重置无敌计时器。
4. 记录本次受击方向 `_getHitDirection`。
5. 调用 `ApplyDamage(damage)` 扣血。
6. 触发 `Player_HealthUpdate` 事件，通知 UI 更新血条。

玩家死亡状态由 `_isDead` 记录，状态机可以通过 `EPredicate.Dead` 查询。

### 玩家击退和受击表现

击退不是在 `TakeDamage` 里直接执行，而是由状态机动作触发：

```text
ActionState
  -> FormUnarmed / FormSword
      -> EAction.Knockback
          -> PlayerHealth.DoKnockback()
```

`DoKnockback()` 使用本次受击方向和配置里的 `GetHitKnockbackForceValue` 执行击退。

`PlayerHealth.GetHitAnimEvent()` 是动画事件入口：

- 摄像机震动：`GameManager.Instance.CameraShake()`
- 受击顿帧：`GameManager.Instance.DoHitStop(_healthConfig.GetHitStopTime)`

## 怪物血量实现

怪物一般使用通用 `Health`，自己实现 `IDamageable`。

典型结构：

```csharp
[RequireComponent(typeof(Health))]
public class XxxMonster : MonoBehaviour, IDamageable, ITouchDamageable
```

### `Minion`

位置：`Assets/Scripts/Character/Monster/Minion/Minion.cs`

流程：

1. `Start()` 中 `_health.Initialize(_maxHealthAmount, _maxHealthAmount)`。
2. `TakeDamage` 里先判断 `_health.IsDead`。
3. 扣血后如果死亡，播放溶解动画并销毁对象。
4. 启动受击协程，变红并执行击退。

### `SpiderController`

位置：`Assets/Scripts/Character/Monster/Spider/SpiderController.cs`

流程：

1. `Start()` 中按 `SpiderConfig.MaxHealthAmount` 初始化。
2. `TakeDamage` 扣血并播放受击变色。
3. 死亡后切到 `SpiderDeathState`。
4. 触发 `Game_BossDead` 事件通知外部 Boss 已死亡。

蜘蛛额外有一个 `HealthAmount` 字段参与技能逻辑，目前它不是 `Health.CurrentHealthAmount` 的直接封装，属于旧逻辑遗留，后续重构时应该统一。

### `FoxBoss`

位置：`Assets/Scripts/Character/Monster/Fox/FoxBoss.cs`

流程：

1. 子类初始化时调用 `Health.Initialize(...)`。
2. `TakeDamage` 里扣血并播放受击变色。
3. 具体死亡行为由 `FoxOneController` / `FoxTwoController` 等子类继续处理。

## 伤害来源

### 玩家攻击怪物

位置：`Assets/Scripts/Character/Player/StateMachine/Components/Attacker.cs`

攻击动画事件触发 `AttackAnimEvent()`：

1. 使用 `Physics2D.OverlapBoxAll` 检测攻击范围。
2. 筛选 `AttackCheckLayer`。
3. 对命中的 `IDamageable` 调用 `TakeDamage`。
4. 伤害值来自 `IAttackConfig.AttackDamage`。

### 怪物触碰伤害

位置：`Assets/Scripts/Character/Monster/Common/TouchHit.cs`

流程：

1. 玩家进入怪物触碰伤害区域。
2. `TouchHit` 判断怪物父级 `Health.IsDead`，死了就不造成伤害。
3. 从怪物根节点获取 `ITouchDamageable.GetTouchDamage()`。
4. 对玩家调用 `IDamageable.TakeDamage`。
5. `OnTriggerStay2D` 内有 1 秒间隔，避免玩家卡在怪物体内时每帧受伤。

### 怪物技能和子弹

常见入口：

- `SlimeAmmo`：命中玩家后调用 `IDamageable.TakeDamage`。
- `SpiderSkillVenomBiteState`：毒牙命中后先调用 `TakeDamage`，后续持续毒伤直接调用 `player.Health.ApplyDamage`。
- `SkillShakeHit`：蜘蛛蛛网伤害，触发后调用玩家 `TakeDamage`。
- `MournfulGazeDebuff`：持续 Debuff，定时调用目标 `TakeDamage`。

这里有一个差异：持续毒伤直接调用 `ApplyDamage`，会绕过无敌时间、受击事件和 UI 更新事件。除非这是刻意设计，否则后续应该改成统一走 `TakeDamage` 或补事件通知。

## UI 更新链路

玩家血条不是直接绑定 `PlayerHealth`，而是通过事件更新。

事件类型：

```text
E_EventType.Player_HealthUpdate
```

事件参数：

```csharp
PlayerHealthUpdateEventArgs(maxHealthAmount, currentHealthAmount)
```

触发位置：

- 玩家 `TakeDamage` 后。
- `GameManager` 初始化主面板后，主动发一次当前血量。
- 恢复血量、奖励提升最大血量后，手动触发一次。

接收位置：

- `GamePanel.OnEnable()` 注册监听。
- `GamePanel.OnPlayerGetHit()` 调用 `UpdateHpBar()`。
- `UpdateHpBar()` 用 `CurrentHealthAmount / MaxHealthAmount` 设置 `_hpImage.fillAmount`。

## 当前设计问题

### 1. 玩家和怪物血量系统重复

`Health` 和 `NewHealth` 都有：

- 最大血量。
- 当前血量。
- 死亡标记。
- `Initialize`
- `ApplyDamage`
- `RestoreHealth`

区别是玩家版多了状态机事件、无敌、击退和 UI 通知。

后续更干净的方向是抽一个通用血量核心，再让玩家/怪物各自组合表现逻辑。

### 2. `ApplyDamage` 可以被外部绕过

`ApplyDamage` 是 public，外部可以直接扣血。

这样会绕过：

- `IDamageable.TakeDamage`
- 无敌时间
- 受击事件
- UI 更新
- 击退方向记录

蜘蛛毒伤现在就是这种情况。这个写法能跑，但不统一。

### 3. `Health` 没有事件

怪物死亡、受击表现都写在各个怪物 Controller 里。

优点是直观。

缺点是怪物多了以后会重复写：

- 死亡判断。
- 受击变色。
- 击退。
- 死亡事件。
- 销毁或回池。

### 4. 蜘蛛存在双血量字段

`SpiderController` 同时有：

- `Health.CurrentHealthAmount`
- `SpiderController.HealthAmount`

后者还参与技能判断和治疗逻辑，容易和真实血量不同步。

这个属于明显的重构目标。

---

## 推荐重构方向

当前阶段不建议一口气大改。

推荐顺序：

1. 先统一规则：外部造成伤害尽量只走 `IDamageable.TakeDamage`。
2. 把 `ApplyDamage` 的外部调用收窄，避免绕过受击流程。
3. 清理蜘蛛的 `HealthAmount`，改用 `Health.CurrentHealthAmount`。
4. 再考虑把 `Health` / `NewHealth` 抽成一个通用血量核心。

更简单的短期方案：

- 保留两套血量组件。
- 只把“绕过 `TakeDamage` 的伤害入口”整理掉。
- 怪物重复逻辑暂时不抽象，等怪物数量更多时再抽。
