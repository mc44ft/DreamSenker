# 健康系统重构方案

## 重构原因

当前健康系统最大问题是：玩家和怪物使用两套血量实现。

具体痛点：

- 怪物、Boss、蜘蛛丝使用 `Assets/Scripts/Health/Health.cs` 保存真实血量。
- 玩家使用 `Assets/Scripts/Character/Player/StateMachine/Components/NewHealth.cs` 自己保存真实血量。
- `Health` 和 `NewHealth` 都重复实现了最大血量、当前血量、死亡标记、扣血、回血。
- `PlayerHealth` 只是继承 `NewHealth`，玩家血量逻辑实际分散在 `NewHealth` 和 `PlayerHealth` 两个脚本里。
- 部分外部逻辑直接调用 `Player.Health.ApplyDamage()`，容易绕过 `TakeDamage()` 里的受击规则。

对应调用链：

```text
怪物受击
  -> MonsterController.TakeDamage()
  -> Health.ApplyDamage()

玩家受击
  -> PlayerHealth.TakeDamage()
  -> NewHealth.ApplyDamage()
  -> NewHealth 内部字段
```

不重构的问题：

- 后续改血量规则时，玩家和怪物要改两套代码。
- 玩家血量无法复用通用 `Health`，健康系统没有统一数据源。
- `NewHealth` 名字和职责都不清楚，继续扩展会让玩家状态机组件越来越乱。
- `ApplyDamage()` 的外部调用语义不统一：有的地方只是扣血，有的地方还期望 UI 更新。

---

## 重构目标

本次重构只解决“两套血量系统割裂”的问题，不扩展成完整战斗系统重构。

完成标准：

- 所有真实血量数据统一保存在 `Health`。
- 玩家不再通过 `NewHealth` 保存 `_maxHealthAmount`、`_currentHealthAmount`、`_isDead`。
- `PlayerHealth` 改为组合 `Health`，只负责玩家专属受击规则。
- 怪物继续使用现有 `Health + IDamageable` 模式，不重构怪物死亡表现。
- 玩家对外接口尽量保持不变，减少 `GameManager`、UI、状态机调用点改动。

保持不变的行为：

- 玩家受击仍然有无敌时间。
- 玩家受击仍然能触发状态机 `EPredicate.TakeDamage`。
- 玩家死亡仍然能通过 `EPredicate.Dead` 判断。
- 玩家血量变化仍然触发事件类型枚举值 `E_EventType.Player_HealthUpdate` 更新 UI。
- 玩家击退仍然由状态机动作 `EAction.Knockback` 触发。
- 怪物、小怪、Boss 的受击表现和死亡表现不变。

职责重新归属：

- `Health`：唯一血量数据源。
- `PlayerHealth`：玩家受击规则适配器。
- 怪物 Controller：怪物自己的受击表现和死亡表现。
- `NewHealth`：删除。

---

## 重构完成后的代码结构

重构后结构：

```text
Health
  - MaxHealthAmount
  - CurrentHealthAmount
  - IsDead
  - Initialize()
  - ApplyDamage()
  - RestoreHealth()
  - OnHealthChanged
  - OnDead

PlayerHealth
  - 持有 Health
  - 实现 IDamageable
  - 实现 IComponent<IHealthConfig>
  - 处理无敌时间
  - 处理状态机受击谓词
  - 记录击退方向
  - 触发玩家血条 UI 事件
  - 处理受击动画事件里的震屏和顿帧

Minion / SpiderController / FoxBoss
  - 持有 Health
  - 实现 IDamageable
  - 自己处理受击表现和死亡表现
```

主要调用链：

```text
普通伤害打到玩家
  -> PlayerHealth.TakeDamage(damage, attackDirection)
  -> 判断无敌时间
  -> Health.ApplyDamage(damage)
  -> PlayerHealth 触发 E_EventType.Player_HealthUpdate 事件
  -> 状态机通过 EPredicate.TakeDamage / Dead 感知受击和死亡

直接血量变化打到玩家
  -> PlayerHealth.ApplyDamage(damage)
  -> Health.ApplyDamage(damage)
  -> PlayerHealth 触发 E_EventType.Player_HealthUpdate 事件

怪物受击
  -> MonsterController.TakeDamage(damage, attackDirection)
  -> Health.ApplyDamage(damage)
  -> MonsterController 自己处理变红、击退、死亡状态
```

数据流向：

```text
PlayerFormConfig / PlayerSaveData
  -> FormStrategy.SwitchSetup()
  -> PlayerHealth.Initialize()
  -> Health.Initialize()
```

## 重构执行计划

### `Assets/Scripts/Health/Health.cs`

改动项：

- 保留它作为唯一血量数据源。
- 增加 `OnHealthChanged` 事件。
- 增加 `OnDead` 事件。
- `Initialize()`、`ApplyDamage()`、`RestoreHealth()` 在血量变化后触发 `OnHealthChanged`。
- `Death()` 只负责设置 `IsDead = true` 并触发 `OnDead`。

改动前：

- `Health` 只保存血量和死亡标记。
- 血量变化后没有事件。
- 怪物 Controller 只能自己在 `TakeDamage()` 后判断 `IsDead`。

改动后：

- `Health` 仍然不实现 `IDamageable`。
- `Health` 仍然不处理 UI、击退、动画、状态机。
- `Health` 提供统一血量变化通知，玩家和未来系统可以订阅。
- 现有怪物逻辑不需要立刻接入事件，原有 `IsDead` 判断继续可用。

### `Assets/Scripts/Character/Player/StateMachine/Components/PlayerHealth.cs`

改动项：

- 删除 `: NewHealth` 继承关系。
- 改为 `: BaseComponent<IHealthConfig>, IDamageable`。
- 添加 `[RequireComponent(typeof(Health))]` 和 `[RequireComponent(typeof(Rigidbody2D))]`。
- 在 `Awake()` 中缓存 `Health` 和 `Rigidbody2D`。
- 迁移 `NewHealth` 中的玩家受击逻辑。
- `MaxHealthAmount`、`CurrentHealthAmount`、死亡判断全部转发给 `_health`。
- `Initialize()`、`ApplyDamage()`、`RestoreHealth()` 内部调用 `_health`。
- `TakeDamage()` 保留无敌时间、受击事件、击退方向记录。
- `Evaluate(EPredicate.Dead)` 改为读取 `_health.IsDead`。
- 血量变化后统一触发事件类型枚举值 `E_EventType.Player_HealthUpdate`。
- 保留 `GetHitAnimEvent()` 中的震屏和顿帧。

改动前：

- `PlayerHealth` 继承 `NewHealth`。
- 真实血量字段在 `NewHealth`。
- 玩家专属动画事件在 `PlayerHealth`。
- 一个玩家健康组件拆成了父类血量逻辑和子类表现逻辑。

改动后：

- `PlayerHealth` 自己就是玩家健康组件入口。
- 真实血量来自同物体上的 `Health`。
- 玩家专属规则全部集中在 `PlayerHealth`。
- 外部继续通过 `Player.Health.Initialize()`、`Player.Health.RestoreHealth()`、`Player.Health.CurrentHealthAmount` 使用玩家血量。

### `Assets/Scripts/Character/Player/StateMachine/Components/NewHealth.cs`

改动项：

- 删除该脚本。

改动前：

- `NewHealth` 同时承担血量数据、无敌、受击事件、击退方向、UI 通知、状态机谓词。
- 它和通用 `Health` 重复保存真实血量。

改动后：

- 血量数据职责回到 `Health`。
- 玩家受击规则职责回到 `PlayerHealth`。
- 项目里不再存在第二套血量数据源。

### `Assets/Scripts/Character/Player/StateMachine/PlayerController.cs`

改动项：

- 给玩家控制器增加 `[RequireComponent(typeof(Health))]`。
- 保留 `[RequireComponent(typeof(PlayerHealth))]`。
- 不改 `Health` 属性对外语义，仍然返回 `PlayerHealth`。

改动前：

- 玩家只强制要求 `PlayerHealth`。
- 玩家是否具有通用 `Health` 不由代码约束。

改动后：

- 玩家对象同时明确要求 `Health` 和 `PlayerHealth`。
- `PlayerController.Health` 继续表示“玩家健康规则入口”，不是通用 `Health`。

### `Assets/Scripts/Character/Player/StateMachine/FormStrategy/FormStrategy.cs`

改动项：

- 保持 `_health.Initialize(_formConfig.MaxHealthAmount, _playerSaveData.CurrentHealth)` 调用方式不变。
- 确认 `_health` 类型仍为 `PlayerHealth`。
- 只调整相关注释，把“初始化玩家血量组件”明确为“通过 PlayerHealth 初始化底层 Health”。

改动前：

- 形态切换时直接初始化 `PlayerHealth`。
- 实际初始化的是 `NewHealth` 内部字段。

改动后：

- 形态切换仍然初始化 `PlayerHealth`。
- `PlayerHealth` 再把最大血量和当前血量写入底层 `Health`。

### `Assets/Scripts/Character/Monster/Spider/States/SpiderSkillVenomBiteState.cs`

改动项：

- 保留持续毒伤调用 `player.Health.ApplyDamage(...)`。
- 重构后该调用会进入 `PlayerHealth.ApplyDamage()`，再转发到 `Health.ApplyDamage()`。
- `PlayerHealth.ApplyDamage()` 必须触发事件类型枚举值 `E_EventType.Player_HealthUpdate`，保证持续毒伤更新 UI。

改动前：

- 持续毒伤调用 `player.Health.ApplyDamage(...)`。
- 实际调用 `NewHealth.ApplyDamage()`，只扣血，不触发 UI 更新。

改动后：

- 持续毒伤仍然调用 `player.Health.ApplyDamage(...)`。
- 实际调用 `PlayerHealth.ApplyDamage()`。
- 扣血后统一刷新玩家血条。

## 重构计划执行顺序

1. 修改 `Health.cs`，先补齐 `OnHealthChanged` 和 `OnDead`，保证通用血量核心可通知外部。
2. 修改 `PlayerHealth.cs`，让它组合 `Health`，并迁移 `NewHealth` 的玩家受击逻辑。
3. 修改 `PlayerController.cs`，补上 `Health` 的组件约束。
4. 修改 `FormStrategy.cs` 注释，确认形态切换仍然通过 `PlayerHealth.Initialize()` 初始化血量。
5. 检查 `SpiderSkillVenomBiteState.cs` 的持续毒伤调用，确认它现在会通过 `PlayerHealth.ApplyDamage()` 更新 UI。
6. 搜索 `NewHealth` 引用。
7. 删除 `NewHealth.cs`。
8. 编译检查。
9. 进入游戏验证玩家受击、毒伤、回血、切换形态、死亡状态谓词。

## 注意项

### 重构风险

- `PlayerController` 和 `PlayerHealth` 必须通过 `[RequireComponent(typeof(Health))]` 保证代码侧组件约束，重构方案不安排修改 Prefab。
- `PlayerHealth.ApplyDamage()` 必须触发 `E_EventType.Player_HealthUpdate` 事件，否则持续毒伤、脚本直扣血仍然会出现血条不同步。
- `TakeDamage()` 和 `ApplyDamage()` 要明确区分：
  - `TakeDamage()`：普通受击，走无敌、受击状态机事件、击退方向。
  - `ApplyDamage()`：直接血量变化，不走无敌，但必须刷新 UI。
- 删除 `NewHealth.cs` 前必须确认没有代码引用它。

### 不采用的重构方式

不让 `Health` 直接实现 `IDamageable`。

原因：

- `Health` 只知道怎么扣血。
- `IDamageable` 代表“被打后怎么响应”。
- 玩家、小怪、Boss、可破坏物的受击响应不同。

所以本次结构固定为：

```text
Health = 血量核心
PlayerHealth / MonsterController = 受击规则入口
```

### 当前方案的好处

- 真实血量统一到 `Health`。
- 玩家专属规则集中在 `PlayerHealth`。
- 怪物现有实现不被打乱。
- `GameManager`、UI、状态机大部分调用不需要改。
- 重构范围只压在玩家健康组件和通用血量核心上。

### 用户可以学到的知识点

- 组合优于继承：`PlayerHealth` 持有 `Health`，而不是继承另一套血量实现。
- 职责分离：血量核心不处理表现，表现层不保存重复数据。
- 适配器思路：`PlayerHealth` 是玩家规则对通用 `Health` 的适配层。
- API 兼容：保留原有 `Player.Health` 调用入口，可以降低重构冲击面。
