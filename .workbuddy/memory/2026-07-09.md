# 2026-07-09

## AddressableManager.cs 代码审查（仅分析，未改动）

审查了 `Assets/Scripts/Addressable/AddressableManager.cs`，发现多个严重 bug，待用户决定是否修复：

- **致命 bug**：三个 Load 方法在 `Completed` 回调里访问 `_assetInfoDict[key]`，但 key 从未插入字典，必抛 `KeyNotFoundException`；handle 也从未存入字典，引用计数机制完全失效，去重也失效（并发同 key 会各自创建 handle）。
- **Release 无法释放 label/多资源加载**：`Release<T>` 的 key 拼接为 `name + "_" + typeof(T).Name`，与带 label 和 `LoadAssetsAsync` 的 key 不匹配，必然泄漏。
- **`LoadAssetsAsync` 回调类型错误**：handle 实际是 `IList<T>`，却用 `Convert<T>().Result` 传给 `Action<T>`，运行失败。
- **`TryGetCache` IsDone 分支不检查 Status**，失败 handle 会异常。
- 加载失败时调用方无任何通知。
- `using Unity.VisualScripting.Dependencies.NCalc;` 无用污染依赖。
- key 字符串拼接可能碰撞（name 含 `_`）。
- 缺 CancellationToken / 失败回调。

结论：整个引用计数和缓存机制目前是坏的，需要重构而非小修。
