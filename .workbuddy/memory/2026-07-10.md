# 2026-07-10

## AddressableManager 审查（第四轮，仅分析未改动）

发现新设计缺陷：**name 和 label 共用 key 前缀空间，重名时缓存污染。**

- `LoadAssetAsync<T>(name)` 和 `LoadAssetsAsync<T>(label)` 生成的 key 都是 `name/label + "_" + T`，name=label 时完全相同。
- 后果：先加载单资源再加载同名 label（或反过来），`TryGetCache` 命中错误 handle，单资源 handle 被当 `IList<T>` 取 / `IList<T>` 被当单个取，类型不匹配报错。
- 不是误操作，Addressables 允许 address 和 label 重名。
- 推荐方案：key 加前缀隔离命名空间，`"asset:" + name` vs `"label:" + label`。
