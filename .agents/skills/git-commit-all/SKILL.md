# Git 全量提交

当用户要求提交代码时：

- 默认理解为“提交当前所有改动”。
- 不要询问提交范围，除非用户明确要求拆分提交或排除文件。
- 提交过程中不要额外执行检查、测试、格式化、清理、空白字符修复。
- 未经用户明确允许，不要在提交过程中修改任何文件。
- 只使用这个简单流程：

```bash
git add .
git commit -m "<主题>" -m "<正文>"
```

提交信息规则：

- 除非用户另有要求，否则提交信息使用中文。
- 根据当前对话和代码改动的实际作用推断提交信息。
- 提交信息默认使用”一个主题 + 多条正文”的格式。
- 主题用一句话概括核心目的，优先使用”动词 + 对象”的形式。
- 正文每条用短句，按改动模块列出，做到多而简洁、多而不乱。
- **代码改动**：改动超过 3 个文件时，必须写正文条目，具体列出每个改动点。
- **文档改动**：简要写提交信息即可，无需详细列出每个改动点。
- 删除文件、规则改动、Unity 资产或 `.meta` 已在工作区中被提交时，提交信息里要明确提到。
- 提交信息应尽可能覆盖主要改动点，但不要写长段解释。

示例：

```bash
git add .
git commit -m "重构健康系统并调整玩家状态机" -m "- 合并 Health 与 PlayerHealth 的血量职责
- 删除 NewHealth 旧健康组件
- 调整 PlayerController 初始化位置
- 更新健康系统重构方案规范"
```
